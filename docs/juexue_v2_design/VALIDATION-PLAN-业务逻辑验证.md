# 新设计业务逻辑验证计划（场景模拟 v2）

> 创建：2026-06-02
> 对象：五层 SoT（05 战略 / 02 权限 / 06 业务能力 / 08 数据层 / 09 API·页面）
> 方法：把设计文档当成系统，用真实场景**端到端走一遍**，找断点 / 矛盾 / 未定义状态 / 越权口子 / 依赖断裂。
> 适用人：**不写代码的产品经理 + Claude Code**——PM 用白话说"模拟 XX 学员走 YY 流程"，Claude 对照文档推演、列缺口，PM 拍板。
> 与已有报告关系：reports/03（符合大纲）+ reports/04（设计完整）已验"对不对/全不全"两角度；**本计划补第三角度——"端到端流程跑不跑得通"**。旧 `docs/SCENARIO_SIMULATION.md`/`BL_REVIEW.md` 基于旧设计（5-25），仅作方法模板，不直接复用。

## 一、五类走查（验证维度）

| # | 走查 | 找什么 |
|---|---|---|
| **D1 端到端场景** | 一条真人旅程逐步追，每步问"有落点吗？数据从哪来到哪去？" | 断点、数据来源缺失 |
| **D2 状态机完整** | 列实体状态转换，查死角 | 未定义转换、回不去的死状态 |
| **D3 权限矩阵** | 每操作 × 每角色 = 能/不能（三端分离铁律） | 越权口子、没人能做的操作 |
| **D4 边界/异常** | 边缘情况有无定义 | 缺口、规则打架 |
| **D5 依赖闭环** | 追跨能力依赖链 | 依赖断裂（A 要 B 数据但 B 没产出） |

## 四、推进波次（从 20 域全集里按优先级挑）

> 180 条不是平摊跑。按"骨架先立、横切再补、净资产后扫"分 7 波；每波从相关域抽场景串成端到端旅程。

**横向验证三件（W5 展开）**：
- **ST 状态机**（8 个）：cohortStatus / 报数快照 / 邀请码三态 / 升学预检 / 自学 / 关怀清单 / 特殊身份 / 完成判定（app-kill）

## 六、预判会撞到的问题（头脑风暴·待验证确认）

> 以下是制定计划时预感的"可能有问题处"，作为走查的重点关注，不是结论：

- **E-02/E-04**：A3 选专业锁定、F7.2 留级次数——已知缺口，流程里会现形。
- **G-04 报数 ↔ L-05 自学**：自学不报数，但若自学学员后来入班，历史完成量怎么接进报数？衔接点需验。
- **G-06 传承自动派生 ↔ DR-143 完成纯手动**：课程"听完"现在是手动确认，自动派生传承的触发时机要确认不漏。
- **S-07 跨专业共享 ↔ G-04 报数快照**：跨专业累计的"果"在哪个专业的报数节点结算？口径需验（接 F3.7 起修日口径）。
- **M-04 辅导员 ↔ G-01 代行**：辅导员"建议代行"路由给谁、管理员怎么收到？流程链需验。
- **ST 完成判定 app-kill**：localStorage 续播 + 延迟确认的"未确认会话"，跨场景（换设备/清缓存）边界。
- **SC-05 约修打卡（⏸后台）↔ BS 报数**：约修贡献打卡复用 PracticeLog，会不会误进升学报数？数据交互边界需验。
- **TM-06/07 并发**：两管理员同时给同一学员代行/改状态；操作进行中角色被 revoke——这类并发/中途态设计文档基本没覆盖，是典型盲区。
- **TM-09 阈值临界**：276座/138h/10万/30min/60s/90% 这些数，"恰好等于"算不算达标？设计里 ≥ 还是 >，要逐个确认一致。
- **AC-08 注销↔重注册**：软删后同邮箱能否重注册、历史档案怎么处理（DeletedEmail）。
- **TM-02 休息周/放假**：CohortRestWeek 对进度基准/掉队判定/报数节点的影响，跨多能力，易漏。
- **ER-08 数据源未就绪**：升学预检跑时报数快照还没生成 / 关怀检测时 CohortLagSnapshot 还没算——时序依赖的"空指针"风险。
