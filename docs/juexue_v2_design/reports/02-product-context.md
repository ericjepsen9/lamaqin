## 1. 项目是什么？目标用户是谁？

觉学（Juexue v2）是一个藏传佛教在线学习平台，主要面向北美和台湾市场。平台的核心价值是提供系统化的「闻·思·修」学习路径，以班级形式组织学员进行集体修学，并围绕殊胜日、法会、共修等仪式节点增强持续参与感。主要用户是跟班修学的学员，辅以带领班级的辅导员和管理平台的 admin。

## 3. 概念定义与角色

### 核心概念

| 概念 | 定义 |
|---|---|
| **课程（Course / 法本）** | 一部佛法典籍，下分章节（Chapter）和课时（Lesson），有封面、作者、类别 |
| **课时（Lesson）** | 法本的最小学习单元，包含正文、题目、观修视频、讲法视频/音频（后两项设计未实施）|
| **学员（Student）** | 主要用户，通过邀请码加入班级进行修学 |
| **修学（Practice）** | 念诵咒语/修法的行为，以遍数或时长计量，记录到修学项目（PracticeProject）下 |
| **打卡** | 即修学计数，记录一次修学行为，写入 PracticeEntry（旧）/ PracticeLog（新设计）|
| **功课 / 作业** | 老师布置的修学任务（ASSIGNMENT_PLAN.md，已设计未实施，Phase 1 优先级最高）|
| **观修** | 法师引导的坐修视频（Meditation），学员观看后记录完成状态 |

### 学员类型

文档未设学员等级制度，但有两类学习模式（新设计）：
- `class`：跟班学习（默认）
- `self_study`：自学（无班级，记录仅自己和 admin 可见）
- `both`：混合

### 角色

> ⚠️ **下表是线上现状/旧系统的 3 角色，非目标设计**。**新设计已改为 4 个管理角色 + 学员**：`class_tutor`（辅导）/ `class_admin`（班级行政拍板）/ `subject_admin`（学科）/ `super_admin`（平台）+ `student`——权威定义见 `decisions/02-roles-and-permissions-v1.md`（D6 四角色 / D7 等级继承 / D8 多角色+作用域）。迁移路径 **DR-113**：`coach → class_tutor`（不自动给行政权，行政权由 subject_admin 人工补授 class_admin）、`admin → super_admin` 后人工降级该降的为 `subject_admin`。本表仅作旧系统背景参考。

| 角色（线上现状·旧）| 说明 | 新设计去向 |
|---|---|---|
| **student（学员）** | 主要用户，跟班修学 | 保留 `student` |
| **coach（辅导员 / 主麦）** | 带领班级，发公告、排课、看学员数据 | → `class_tutor`（行政权另授 `class_admin`，DR-113）|
| **admin（管理员）** | 平台管理，建班级/法本/题目/配置 LLM | → `super_admin` / `subject_admin`（DR-113）|

辅导员在 ROADMAP 中称「老师」（可布置功课），在代码和 PRODUCT_OVERVIEW 中统一称 coach。无「组长」角色。

## 4. 修学流程

### 报名入班

1. admin 创建班级，设置 joinCode（6-8 位邀请码）
2. 辅导员分享邀请码给学员
3. 学员输入邀请码加入班级 → Onboarding 引导流程

无公开班级目录，目前只能靠邀请码（CLASS_DISCOVERY_PLAN.md 中「公开班级目录 + 申请加入」已设计未实施，Phase 2 范围）

### 日常学习

- **闻**：进入法本 → 阅读课时 → 自动记录进度 → 段落加笔记/高亮
- **思**：课时末尾题目 → 答题 → AI 评分 → 错题进错题本 → SM-2 自动安排复习
- **修**：点修学计数 → 滚轮选遍数（设计未实施，现状不明）→ 写 PracticeEntry
- **观修**：进观修视频 → 完成 → 写 MeditationSession

辅导员可为班级排课（共修/答疑/直播 ClassSession），触发提醒通知。

### 学习成果验证

- 进度：阅读进度自动追踪（heartbeat + scroll）
- 修学排行：班级内按遍数/时长排名（学员可选择隐藏）
- 辅导员看板：班级修学统计 + 观修完成情况
- 无明确考试或结业机制（ROADMAP 和 PRODUCT_OVERVIEW 均无提及）

## 5. ROADMAP 中是否有「预科/正科/加行/传承/分阶段培训体系」？

**ROADMAP_2026.md 提到了以下内容：**

- **「加行」**：出现在 DESIGN_DECISIONS.md 中作为科系示例（加行/净土/入行论），但 ROADMAP_2026.md 本身未提及
- **传承**：决策第 10 条明确写「上师传承 不做」
- **预科 / 正科**：两份文档均未出现此概念
- **分阶段培训体系**：ROADMAP_2026.md 的「Phase」指的是开发阶段（Phase 1-4），不是学员的培训阶段

ROADMAP 中与「体系」最接近的表述是 F2「功课系统（含老师布置）」，支持老师给班级布置不同类型的修学任务，但未涉及学员在体系内的阶段晋升或培训层级。

**结论（⚠️ 旧基线·已被新设计整体推翻）：~~目前两份文档中没有「预科/正科」或分阶段培训体系的概念，「加行」只作为一个科系名称出现，传承明确不做~~**——以上是旧产品状态；**新设计正是建立预科/正科×专业×8 学期体系（D1/D2/D3）+ 传承必做（D4）+ 考试升学（D13）**。本节仅记录"改造前两份旧文档里没有这些"，不代表现状。
