## P0：必须做独立设计验证（5个）

> 按依赖顺序排序：能力39 → 能力3 → 能力4 → 能力8 → 能力18

---

### P0-1：能力39 音视频学习 + 分维度完成

**为什么优先**：LessonCompletion 是能力3圆满判定的数据来源，先验证数据层。

| 验证重点 | 具体场景 |
|---|---|
| 多专业独立计数 | 同一课时在专业A和专业B分别记录，互不干扰 |
| 无障碍状态分支 | 盲学员只需听，聋学员只需读，进度页各自正确展示 |
| 四维度独立 | listen/read/watch/quiz各自独立计数；只看不听时圆满计数正确 |
| 新vow起修日截断 | 留级后新vow，旧vow的LessonCompletion是否正确排除 |
| 与能力3数据接口对齐 | LessonCompletion喂给圆满判定的字段名和值域 |

---

### P0-2：能力3 闻思学习与圆满判定

**为什么关键**：直接控制升学资格，无障碍分支逻辑复杂，算错无声堵升学。

| 验证重点 | 具体场景 |
|---|---|
| 三类课程分支 | 入门课/正式课/限制课各自圆满条件不同 |
| 无障碍分支 | 普通×盲×聋：3条路径的听/看/读组合 |
| 答题对圆满的影响 | 必答题未完成是否卡圆满；开放题自评路径 |
| 多专业隔离 | 专业A圆满不跨到专业B |
| 圆满结果喂给升学预检 | 升学第一条件「全部课程闻思圆满」是否正确读到 |

---

### P0-3：能力4 加行观修

**为什么关键**：双维度 + 起修日截断 + 留级重算三重逻辑叠加，升学预检依赖它。

| 验证重点 | 具体场景 |
|---|---|
| 双维度同时满足 | 座数够但时长不够→不达标；时长够但座数不够→不达标 |
| 30分钟最低门槛 | 29分钟的一座是否被排除；30分整是否计入 |
| 起修日截断 | 留级后新vow，旧vow的观修是否排除出升学预检 |
| 多专业独立 | 专业A的92修法不共享给专业B（与内加行的跨专业共享相反）|
| 代行替代场景 | 200万金刚萨埵替代10万顶礼的计算路径 |

---

### P0-4：能力8 共修与出勤

**为什么关键**：升学六条件之一，时效签到机制复杂，30分钟窗口边界容易出bug。

| 验证重点 | 具体场景 |
|---|---|
| 时效签到链接 | 链接过期后签到被拒；迟到30分钟内可签；30分钟后不可签 |
| 三类出勤独立计数 | 线上/线下/自修各自计数 |
| 自学模式学员不计出勤 | 自学模式下出勤字段不写入；升学预检出勤项的边界处理 |
| 多专业独立计数 | 同一场共修，参与两个专业的学员出勤各自记录 |
| 出勤喂给升学预检 | 升学第四条件「共修出勤达标」正确读取 |
| 留级后重算 | DR-181：只计新届active班级出勤，前届不累入 |

---

### P0-5：能力18 角色与权限

**为什么关键**：权限漏洞无声越权，影响整个平台数据安全。

| 验证重点 | 具体场景 |
|---|---|
| 权限继承链 | class_tutor/class_admin/subject_admin/super_admin各自能做什么、不能做什么 |
| 班级作用域隔离 | A班辅导员无法操作B班数据 |
| 学员同时是辅导员 | 学员端看纯消费视图；管理端看辅导员功能；角色不串 |
| 多角色叠加 | 同一人在A班是辅导员、在B班是管理员，两个作用域各自正确 |
| 角色变更留痕 | AuditLog正确记录授权/撤权操作 |
| super_admin专属操作 | 撤销升学、书面背书忏悔确认等专属端点，class_admin调用被拒 |
