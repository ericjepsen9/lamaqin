# 回归测试剧本 R1：小钱的复杂状态轨迹（专撞修复点）

> 裁判模式·**回归专项**：对照**修复后**的设计（05/06/08/09 + DR-149~154）逐点判断。本剧本不挖旧缺口，专验"9 个修复（graduated/advanced 拆分、disqualified 态、一因两果替代、zhengke_bypass）是否引入**新矛盾/新级联不自洽**"。

## 修复引入的新问题清单（区别于旧缺口）

> 以下 6 条均为 DR-149~154 修复**之后**才出现的问题，单次/单专业路径下不暴露。旧缺口（学员无申请入口、留级 held_back 语义）见文末对照，不计入本清单。

### 🔴 新矛盾（3 个根因）

1. **🔴 zhengke_bypass 跨专业污染（T14）· DR-154** — ✅ **已处置（2026-06-03，议题 A 闭环）**
   bypass 判定"**任意** active 正科"，未校验"该正科是否对应当前预检的专业升学线"。多专业学员一旦在任一正科在读，其**所有**并行预科专业的升学预检都被无条件放行→未达标专业被误判通过。直接抵触 D9/D16。
   修向：bypass 收窄为"**对应升学线**的正科在读才 bypass"（如加行→密法线；净土→其对应正科线），或干脆取消跨专业 bypass、各专业独立预检。
   **处置结论**：取**整体撤销 G1.7-3**（非收窄）。理由——`advanced` 成员本就不进预检，bypass 对其无意义；它真正影响的只有"多专业并存且某专业在读正科"的场景，而该场景下用密法资格为净土背书是类别错误。收窄方案需引入"专业升学线对应表"且仍承认虚构的跨专业等价关系，得不偿失。撤销后回到 D9/D16：每专业 programId 独立跑 6 条件。已同步 06（删能力 10 规则 11、绝对约束 5 改写）/08（§3.9 约束+设计意图+§八 DR-154+changelog）/09（删预检端点 bypass、业务落点 ⑤）。DR-154 仅保留 G1.7-1/G1.7-2。

2. **🔴 advanced→disqualified 未定义 + 抵触 DR-150 终态（T16）· DR-149/DR-150/DR-152**
   DR-149 新增 advanced/disqualified 两态、DR-150 宣称 advanced"永久停留不再改变"，但虚报治理需要对**已升学**学员追溯取消资格。该转换既不在状态机定义内，又与"不再改变"表述冲突。
   修向：明确 advanced→disqualified 是否合法；若合法，定义它对 AdvancementRecord（是否撤销）与下游正科（见下条）的处置。

3. **🔴 二次替代→多心咒 vow→预检非确定性（T5/T6/T10）· DR-94/DR-151** — ✅ **已处置（DR-155，议题C）**
   DR-94"每次替代新建心咒 vow" + DR-151"substitutionFor 反查"默认一对一。撤销后再替代→同一顶礼 vow 被多个心咒 vow 指向→升学预检反查返回多行、无 tiebreak。
   **处置（方案A）**：撤销替代时心咒 vow status→`revoked`（不删除）；再替代时复用同一 vow（reset active+currentCount=0），不新建；预检只取 status=active vow；`UserPracticeVow.status` 新增 revoked 值；substitutionFor 始终一对一。

### ⚠️ 新缺口（3 个）

4. **⚠️ 撤销替代后心咒 vow 孤儿 + substitutionFor 悬空（T4）· DR-151 未回溯更新撤销流** — ✅ **已处置（DR-155，议题C）**
   DR-151 在剧本 3 之后才加 substitutionFor，但能力 5 的 revoke 流程未同步定义"撤销时如何处置心咒 vow 及其 substitutionFor"。剧本 3 T13 的反向级联缺口在修复后**变形延续**（现在还多了悬空指针）。**处置**：撤销时心咒 vow status→revoked（保留，D18），substitutionFor 指针保留（历史留档，非悬空）；再替代复用该 vow；见 DR-155。

5. **⚠️ disqualified 对已升入正科（下游专业）的级联未定义（T17）· DR-152** — ⏸ **待定（议题B，2026-06-03）**
   DR-152 只定义了 disqualified 学员自身的 App 访问/再入学/历史重算，未定义"凭被取消资格的预科升上来的正科席位如何处置"。与 DR-150"并行不级联"不是一回事（那是横向并行，这是纵向下游）。当前结果：作废历史却保留毒树之果。

6. **⚠️ disqualified 再入学卡在 ⏸ DR-84 忏悔 gate（T18）· DR-152②←DR-84** — ✅ **已处置（DR-156 D1，议题D）**
   再入学硬性要求"忏悔/认罪流程"，但该 gate 逻辑整体 ⏸ 待定（DR-84）。修复（DR-152 再入学路径）依赖一个未决依赖，端到端走不通。**处置**：改为 super_admin 书面背书（必填忏悔确认说明写 AuditLog），系统不做 gate 检查，不依赖 DR-84，两者解耦；DR-84 继续 ⏸ 待定。

### 🟡 新模糊（1 个）

7. **🟡 D18 历史保留 vs 从 0 重算的视图/机制未说清（T19）· DR-152③** — ✅ **已处置（DR-156 D2，议题D）**
   两规则可共存（档案视图 8 万 / 新轮预检 0），但"再入学是否新建 vow""学员端呈现哪个数"未明文。**处置**：双层视图——档案视图（D18 全历史）永久保留；本期升学进度=新 ClassMember + 新 program_task vow（起始日=新入班日），vowId 隔离旧数据；学员端进度页=本期，档案页=完整历史。
