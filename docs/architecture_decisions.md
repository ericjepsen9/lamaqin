## 决定 #170 · Native / WebView 边界

App 架构 = **原生 RN 为主,WebView 仅特定场景**(不是全 WebView 壳)。

| 类型 | 用什么 | 屏 |
|---|---|---|
| 默认全部 | 原生 React Native | ~35 屏 |
| YouTube 视频(必须) | `react-native-youtube-iframe`(WebView 封装) | S7 |
| 自存视频 | `expo-video`(纯 Native) | S7(如有) |
| 长文排版(可选) | 先纯 RN ScrollView,有复杂排版需求再升级 WebView | S7 法本 / S8 参考答案 / S18 读物 / S16 藏文 |

**判断准绳**:要打字/点按钮/写数据库 = Native;只滚动看长文/看视频 = 可 WebView。

**对技术栈影响**:零冲突。RN Reusables + Zustand 等全部继续有效。`react-native-webview` 本就在 PRD §8 计划内。

**为什么不做全 WebView 壳**:App Store Guideline 4.2 会拒"只是网页包装"的 App;且跟今天锁的原生 RN 技术栈冲突。

## 决定 #171 · 管理端架构 + "发心" Tab(取代身份切换)

### 一套代码 + 响应式

- 师兄端 + 管理端 = 同一个 Expo App,一套代码
- 管理端做响应式布局(NativeWind 断点 `md:` `lg:`),iPad / laptop 浏览器为主入口
- 共享:登录(Supabase Auth)、数据层(查询/Zod/类型)、设计系统、部署

### 取消"身份切换器",改用"发心" Tab

**哲学根基**:上师说"发心就是修行"。照顾班级、利益师兄本身是修行,不该框成"切换到另一个身份"。

师兄端底部 Tab(人人统一,5 个):
```
[首页] [周任务] [修持] [发心] [我的]
```

"发心" Tab 内容**因角色而异**:
| 角色 | 进"发心"看到 |
|---|---|
| 普通师兄 | 发心开示 + 引导(v1.0 静态,见 #173) |
| 主麦 | 我管理的班级卡片(Access Hub) |
| 爱心师兄 | 我关怀的班级卡片(Access Hub) |
| admin | 管理(全部班);系统功能 M1-M10 走"我的"(Profile) |

### admin 系统管理入口

```
admin 不用切换器
"我的"(Profile)→ [系统管理 →] → admin dashboard
                                    ├─ 全部班级卡片
                                    └─ 系统功能区 M1-M10
```

### v1.0 → 未来的渐进优化

- **v1.0(按 A 做)**:管理端代码打包进所有端(最简单)
- **v1.5+(按 C 优化)**:用 `Platform.OS` 把管理端从手机包剔除(省体积)
- 这是优化不是架构变更,随时可加

### 代码纪律(保证 A→C 零返工)

```
app/(student)/   ← 师兄端路由
app/(admin)/     ← 管理端路由
lib/queries/     ← 共享 Supabase 查询
lib/schemas/     ← 共享 Zod schema
lib/types/       ← 共享类型
```

### 角色分流

登录后看 `profiles.role` 决定进哪个区。师兄看不到管理入口 + RLS 数据库层双重拦截。

## 决定 #174 · 掉队检测用规则状态机,AI 推迟

师兄参与度下降(没共修/讲考/打卡/听传承/修行)= **结构化信号,用规则不用 AI**。

| 阶段 | 做法 |
|---|---|
| **v1.0(已在 PRD)** | 4 级 at_risk 状态机 + 爱心 C1 关怀名单(纯 SQL),覆盖 90% 场景 |
| **v1.5+** | "参与度加权评分"(仍是规则,更聪明公式)+ 趋势可视化 |
| **v2.0+(谨慎)** | AI 读"可见主麦"日记的情绪等模糊判断 |

**v2.0 AI 红线**(若将来做):
- 绝不碰 `private` 日记(原则 10)
- 只给爱心师兄"参考",不自动判定/贴标签(原则 1)
- 不替代人工关怀(原则 9)

**核心判断**:规则又快又准又便宜;AI 是锦上添花且带隐私伦理风险。先把规则状态机做扎实。
