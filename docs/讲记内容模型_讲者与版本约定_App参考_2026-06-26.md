# 讲记内容模型 · 讲者与版本约定(App / Eric 参考)

> **解决什么**:数据库里**没有「上师/法师」字段,也没有「版本」字段**——这两件事是用两个机制拼出来的。本文把约定写成可照抄的判据。

## 1 · 三张表,各管一件事

| 表 | 管什么 | 关键列 |
|---|---|---|
| `course_lessons` | 节次轴(权威节号) | `lesson_number`、`title`、`source_text`(造者原文正文) |
| `lesson_resources` | **谁讲的 + 媒体**(一节多行,一行=一个讲者) | `speaker_name`(**自由文本**)、`video_url`、`audio_url`、`download_url`、`sort_order` |
| `lesson_blocks` | **讲记的结构化文字块** | `lesson_resource_id`(**可空 FK → lesson_resources**)、`block_order`、`block_type`、`text_layer`、`text`、`author` |

- `courses.name` = 上师讲记名;`courses.author` = **造论者**(写原典的人,如寂天/龙树/麦彭/无著)。
- `lesson_resources` **没有 `role` 字段**(迁移注释明示);讲者身份只有自由文本 `speaker_name`。
- `lesson_blocks.lesson_resource_id` **可为 NULL**——这是"版本归属"的关键开关(见 §2)。

## 2 · 「上师 / 法师 / 版本」实际是这样编码的(两个维度)

### 维度①:`lesson_resources.speaker_name` = 谁讲的(媒体维度)
- 一节课挂 **1 到 N 行** `lesson_resources`,**每行一个讲者**(各带自己的视频/音频)。
- **"版本数" = 这一节挂了几行 resource。**
- `speaker_name` 是**自由文本,不是枚举**,而且**混了三类东西**:① 真人名(索达吉堪布、智诚堪布、圆函堪姆)② 角色标签(`法师辅导`)③ 内容类型(`观修`)。**别把它当类型枚举用。**

### 维度②:`lesson_blocks.lesson_resource_id` 空/非空 = 这段文字属于哪一版
- **NULL = 默认正文**:讲记课里 = **上师(主讲者)的讲记文字**;原文课里 = **造者原典**(见 §4)。
- **非空 = 挂在某个讲者版本下的文字**(如法师辅导版的文字),通过 FK 指向具体的 `lesson_resources.id`。

> 一句话:**媒体看 `speaker_name` 行;文字看 `lesson_resource_id` 空非空。**

## 3 · App 要"切上师版 / 法师辅导版"——照抄这套判据

对某一节 `lesson_id`:

```sql
-- 上师(默认)讲记正文：
SELECT * FROM lesson_blocks
WHERE lesson_id = :lesson AND lesson_resource_id IS NULL
ORDER BY block_order;

-- 某法师辅导版正文（先拿到该讲者的 resource id）：
SELECT id FROM lesson_resources
WHERE lesson_id = :lesson AND speaker_name = :speaker;   -- 如 '智诚堪布'

SELECT * FROM lesson_blocks
WHERE lesson_id = :lesson AND lesson_resource_id = :resource_id
ORDER BY block_order;

-- 这一节有几个版本 / 都是谁（含纯媒体版）：
SELECT speaker_name, video_url, audio_url, id AS lesson_resource_id
FROM lesson_resources WHERE lesson_id = :lesson ORDER BY sort_order;
```

**注意「纯媒体版」**:某些讲者版本**只有音视频、没有文字块**(`lesson_resources` 有行,但没有任何 `lesson_blocks` 指向它)。App 渲染要前向兼容:**有文字块 → 显示文字;无文字块 → 只给播放器**(web 端就是这么处理的)。

**worked example —— 三戒要解(`sanjieyaojie`)第 1 节**:
- 索达吉堪布 → 1 行 resource(有视频)+ **101 个 `lesson_resource_id IS NULL` 块 = 上师讲记正文**
- 智诚堪布 → 1 行 resource(有音频)+ **168 个挂它 id 的块 = 法师辅导正文**

> ⚠️ **`block_order` 是按版本各自从 0 排的、会跨版本重叠**(实测此节:上师 0–100、智诚堪布 0–167)。
> → **永远先按版本过滤、再 `ORDER BY block_order`,绝不跨版本一起排序。**(上面 §3 的 SQL 已是这个姿势。)

### 多个法师各有文字 —— 完全支持,无需改表
同一节挂多版文字本就是现状(上师 NULL + 智诚堪布 已并存于一节)。再加法师只是**重复同一模式**:
- 每多一个"有文字"的法师 = **多一行 `lesson_resources`(speaker_name=该法师)+ 它的 `lesson_blocks` 挂这行 id**。
- 一节可同时有:`NULL`(上师)+ resourceA(法师1)+ resourceB(法师2)+ … 各自独立、互不干扰。
- **纯文字、无音视频的法师版**也行:`lesson_resources` 的 `video_url`/`audio_url` 留空即可。
- **表上没有任何唯一约束**限制"一节挂多个有文字的讲者"(`lesson_resources`/`lesson_blocks` 只有主键 + 外键,无 `(lesson_id, speaker_name)` 或 `(lesson_id, block_order)` 唯一约束)→ 加多少法师文字都不撞约束。

## 4 · 讲记课 vs 原文课 vs 自学读物 vs 大藏经(别混)

| 类型 | 怎么识别 | NULL 块是什么 | 表 |
|---|---|---|---|
| **讲记课** | 课/节**有 `lesson_resources`**(有讲者) | 上师讲记正文 | `course_lessons`/`lesson_resources`/`lesson_blocks` |
| **原文课**(原典/仪轨原文) | 课/节**一行 resource 都没有**(无讲者) | **造者原典原文**(归属看 `lesson_blocks.author`,如寂天/无著)——**不是讲记** | 同上(只是无 resource) |
| **自学读物** | 完全另一套表 | — | `self_study_books`/`self_study_articles`/`self_study_blocks` |
| **大藏经**(乾隆/龙藏) | 完全另一套表 | — | `canon_*`(对外 `v_public_canon_*`) |

> ⚠️ **可靠区分讲记 vs 原文**:`这门课/这节有没有 lesson_resources?` 有 → 讲记课,NULL 块 = 上师讲记;**没有 → 原文课,NULL 块 = 原典**(别误当上师讲记)。

## 6 · 坑 + 自查

1. **没有 `version` 列、没有 `role` 列**——版本是"算"出来的(resource 行数 + 块的 `lesson_resource_id` 空非空),别去找字段。
2. **`speaker_name` 是自由文本**,`法师辅导`/`观修` 不是人名;要分"上师 vs 法师",实用判据 = `speaker_name = '索达吉堪布'` → 上师,其余 → 辅导/其他。
3. **NULL 块 ≠ 永远是上师**(原文课里是原典),用 §4 的 resource 有无来消歧。
4. **对外视图**:`v_public_media` 直接暴露 `speaker_name AS speaker` + 媒体 URL + `lesson_resource_id`(它也不分类上师/法师)。**讲记文字块没有公开视图**(无 `v_public_lesson_blocks`)——App 只读内容表时**直读 `lesson_blocks` 并自己套本文约定**。

```sql
-- 自查讲者分布
SELECT speaker_name, count(*) FROM lesson_resources GROUP BY 1 ORDER BY 2 DESC;
-- 自查"哪些课多版本、各是谁"
SELECT c.slug, string_agg(DISTINCT lr.speaker_name,' | ') FROM courses c
JOIN course_lessons cl ON cl.course_id=c.id JOIN lesson_resources lr ON lr.lesson_id=cl.id
GROUP BY c.slug HAVING count(DISTINCT lr.speaker_name)>1 ORDER BY 1;
```
