# 隐私姿态 · 项目级原则 · 2026-06-21

> **定稿 · 事实源**。由 `_孵化/query-intelligence/` 的 **D2** 毕业而来(PM 2026-06-21 拍板)。
> 这是**任何「搜索 / 查询 / 用户自由文本」采集动手前**都要先过的那把尺。下游(web / app)扩相关功能前**先读本文件**。
> 锚点:守**红线③ 学员隐私 0 暴露**、在**红线④** 框内;不复制红线正文,只就「查询/搜索文本」这条具体线立姿态。

---

## 0 · 一句话

> **查询文本 = 灵修隐私。** 系统采集一律**零身份**;用户自有功能(若做)走**知情·自有·可删·仅本人·物理隔离**。原始自由文本**短保留**,长期趋势靠**聚合数**而非延长原始文本。

---

## 1 · 为什么「查询文本」是隐私(即使站是公开的)

- **公开的是「页面内容」,不是「谁搜了什么」。** 站公开 = 内容可被收录;用户敲进搜索框的字是个人行为,不因站公开而变成公开信息。
- **这是灵修站。** 查询常是很私人的内心状态(临终 / 抑郁 / 想不通 / 对法的怀疑 / 婚姻痛苦…)。「**某个人搜过这些**」本身就是关于他内心世界的画像 → 正是红线③要守的。
- **风险全在「查询文本 + 身份」的关联**,不在内容公不公开。搜索**结果**那侧没有泄密风险(内容本就公开);要守的只是**查询这一侧**。

---

## 2 · 两套制度(核心 —— 别混)

### A · 系统分析日志(现状,锁死)

> 目的 = 看「大家搜什么、缺什么」(搜索意图 / 缺口信号)。**不做用户画像、不做个性化、不做聚类**(聚类 = D5,围栏 later)。

- **永远零身份**:表里**无 ip / user_id / session / cookie / 任何身份列**。
- **隔离锁死表 + RLS + 只读角色**:anon 不能直接 `SELECT`/`INSERT`,只能经锁死 RPC(`log_search`)写;PM 在 Supabase SQL Editor 读。
- 落地真源 = `Planning/实施计划_搜索意图采集_2026-06-21.md`(D1)。

### B · 用户自有数据(若将来做,如「保存我的搜索」)

> 与 A **性质不同**:A 是系统背着用户做分析(零身份);B 是用户**自己主动**留存**自己的**东西。B 可以绑身份,但**门槛很高**:

- **用户主动 opt-in**:默认不存,用户点了才存。
- **仅本人可见**:RLS 锁到 self —— 别的用户看不到、公开看不到、运营不能随手翻。
- **用户可删**:是他的,他说删就删。
- **与 A 物理隔离**:B 是独立的带 `user_id` 表;**绝不因为做了 B 就给 A 的分析日志补上身份列**。两套永不合并。

---

## 3 · 保留期(Retention)

- **原始查询文本**:**6 个月**自动删(pg_cron)。
  - 这是**数据最小化**(留得越短、能泄的越少;自由文本可能夹带 PII)与**低流量站需要累积窗口看出长尾规律**之间的**折中**;6 个月约盖一个学期周期 / 节日法会高峰 / 几波内容上线。
  - 它是**旋钮**:看到真实数据量后可调长 / 隐私上想更保守可调短。
- **聚合统计**(如「词 → 被搜次数」,**无身份、无自由文本**):**可长期留**。想要长期趋势走这条,**不靠延长原始文本的保留**。

---

## 4 · 自由文本 = 可能夹带 PII

- 搜索框是自由输入,偶尔会有人直接敲「我是 XX / 我母亲上周往生…」这类 —— **PII 是用户自己填进文本的,schema 拦不住**。
- 缓解 = **短保留(§3)+ 不接身份(§2A)+ 不外发第三方(§5)**。

---

## 5 · 查询文本留第一方,不进 GA4 / Google

- query **文本**永远留第一方自建库,**不进 GA4 / 任何第三方**。理由:① GA4 的 PII 政策对自由文本有**封号风险**;② 阈值化会**吃掉长尾零结果**(恰是主目标);③ 把 query 绑 `client_id` **违背本姿态 §2A**。
- **零文本的速率信号**(失败率 / 点击率,不含查询文本)用站上已有的 GA4 / Vercel Analytics 即可 —— 那是另一回事,不受本条限制。

---

## 6 · 红线锚点

- **红线③(学员隐私 0 暴露)**:§2B 的「RLS 锁到 self」是它在用户自有数据上的延伸;§1 的判断本身就是红线③。
- **红线④(会员区运行时连库走 RLS)**:A / B 两套都在此框内。搜索端点**首次开始写库** = 红线④「窄豁免」的有意扩展,记录在 `官网子项目_设计纲要 §1`。
