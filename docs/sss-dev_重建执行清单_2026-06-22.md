## 2 · 导出现有数据(data-only,待会灌回)

```bash
# 只导 public 的数据(不含结构),用于灌回新 schema
pg_dump -n public --data-only --no-owner -f sss-dev_public_data.sql
grep -c "^COPY " sss-dev_public_data.sql   # 看有多少张表带数据(应 >0)
```

> 说明:导出按 sss-dev **现有的列**。灌回新 schema 时:新增的列(如 `courses.course_type`)带默认值会自动补;生成列(`lesson_blocks.ts`)由 PostgreSQL 自动重算,**不用管**。

## 3 · 重建 schema(drop public + 还原授权 + 重放迁移)

### 3a. 取分支代码(迁移文件在 `supabase/migrations/`)

```bash
git clone https://github.com/bicw-ny/sss-app.git
cd sss-app
git checkout claude/focused-hamilton-000nc8
ls supabase/migrations/*.sql | wc -l       # 应为 31
```

### 3b. drop + 重建空 public + 还原 Supabase 授权

> ⚠️ 关键:drop public 会丢掉 Supabase 给 anon/authenticated/service_role 的授权和默认权限。
> 不还原的话,重建后 App 会「permission denied」读不到数据。下面这段把它补回来。

```bash
psql -v ON_ERROR_STOP=1 <<'SQL'
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;

-- schema 级授权
GRANT USAGE ON SCHEMA public TO postgres, anon, authenticated, service_role;
GRANT ALL   ON SCHEMA public TO postgres, service_role;

-- 默认权限:之后迁移建的表/函数/序列,自动授权给三个角色(必须在跑迁移前设好)
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES    TO anon, authenticated, service_role;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON FUNCTIONS TO anon, authenticated, service_role;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO anon, authenticated, service_role;
SQL
```

### 3c. 按顺序重放全部迁移(出错即停、报出文件名)

```bash
for f in supabase/migrations/*.sql; do
  echo ">>> $f"
  psql -v ON_ERROR_STOP=1 -f "$f" || { echo "❌ 失败于: $f"; exit 1; }
done
echo "✅ 全部迁移已重放"
```

> 文件名按时间戳排序 = 执行顺序。若停在最后的 `..._search_log_intent_capture.sql` 且报 pg_cron → 回 Pre-flight 第 2 步启用 pg_cron,再从该文件续跑。

## 4 · 灌回数据(先卸外键 → 灌 → 复外键)

> 为什么这么绕:Supabase 的 `postgres` 不是超级用户,不能用 `session_replication_role` 关外键检查。
> 所以用「卸掉所有外键 → 灌数据(顺序就无所谓了)→ 把外键加回来(顺便校验引用完整性)」——这只需表属主权限,postgres 有。

```bash
# 4a. 先把"加回外键"的语句生成好存起来(此刻 schema 是新的、外键齐全)
psql -At -c "SELECT 'ALTER TABLE '||conrelid::regclass||' ADD CONSTRAINT '||quote_ident(conname)||' '||pg_get_constraintdef(oid)||';' FROM pg_constraint WHERE contype='f' AND connamespace='public'::regnamespace;" > fk_readd.sql
wc -l fk_readd.sql      # 看有多少条外键

# 4b. 卸掉所有外键
psql -At -c "SELECT 'ALTER TABLE '||conrelid::regclass||' DROP CONSTRAINT '||quote_ident(conname)||';' FROM pg_constraint WHERE contype='f' AND connamespace='public'::regnamespace;" | psql -v ON_ERROR_STOP=1 -f -

# 4c. 灌数据(此时无外键约束,COPY 顺序无所谓)
psql -v ON_ERROR_STOP=1 -f sss-dev_public_data.sql

# 4d. 把外键加回来(会校验已灌数据的引用完整性)
psql -v ON_ERROR_STOP=1 -f fk_readd.sql
echo "✅ 数据已灌回、外键已复原"
```

> **若 4c 报 `relation "xxx" does not exist` 或 `column "yyy" does not exist`**:说明 sss-dev 有一张/一列分支迁移里**没有**的对象(ETL 线手建、未进迁移)。这正是要捞出来的"非迁移对象"——把报错贴回来,我们一起定它该保留还是丢弃(数据仍在第 1 步的备份里,丢不了)。

## 出事回滚(任一步骤搞砸了)

```bash
# 把 public 清空,从第 1 步的备份恢复(pg_restore 会自动按依赖顺序、最后加外键)
psql -v ON_ERROR_STOP=1 -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;
  GRANT USAGE ON SCHEMA public TO postgres, anon, authenticated, service_role;
  GRANT ALL ON SCHEMA public TO postgres, service_role;"
pg_restore --no-owner -n public -d "postgresql://$PGUSER:$PGPASSWORD@$PGHOST:$PGPORT/$PGDATABASE" sss-dev_public_backup.dump
```

## 为什么这套方案安全(一页纸总结)
- **登录账号不动**:全程只 drop/重建 `public`,`auth.users` 一个字不碰。
- **内容数据不丢**:第 1 步全量备份 + 第 2 步数据导出,两道保险;灌回是 additive(新列补默认、生成列自动算)。
- **结构 100% 对齐分支**:空库跑全套迁移,等于分支的终态 schema(和"全新建库"一个样)。
- **非迁移对象会自曝**:若 sss-dev 有分支没有的表/列,第 4c 步会报错把它指出来,由我们定夺(数据仍在备份里)。
- **不需要 prod 凭据**(方案 A 才需要),也不需要做精细 diff(方案 B 才需要)。
