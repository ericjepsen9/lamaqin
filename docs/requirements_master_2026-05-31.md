# 第一部分:产品与架构

## 1. 产品定位

服务佛学预科学修的 **学修管理 + 实修打卡 + 班级关怀** App(iOS / Android / Web)。承载四专业(加行/净土/入行/学经)4 年 8 学期的闻思与实修,连接四角色,以"地方共修为主、网络共修/自学为辅"运作。

**最高精神总纲:三殊胜**(前行发心 · 正行无缘 · 结行回向),13 原则为其展开。核心气质 = **克制**:不排名、不比较、不推送催促、隐藏总累计目标、师兄端无状态色、关怀靠人工。**这份克制是产品灵魂与差异化,不为功能便利让步。**

## 2. 技术架构(锁定)

- **前端**:Expo (RN + TypeScript)、Expo Router、NativeWind v4、React Native Reusables、Zustand、TanStack Query v5、React Hook Form + Zod、date-fns/-tz、Lucide。约 13 核心依赖。
- **后端**:Supabase(PostgreSQL + Auth + RLS + Storage + Realtime)。
- **一套代码 + 响应式**:师兄端 + 管理端同一 App;`app/(student)`/`app/(admin)`,共享 `lib/queries|schemas|types`。
- **Native/WebView**:默认原生 RN;YouTube 用 youtube-iframe;长文 ScrollView。
- **资料托管(v1.0 已定)**:文字内置;**音频 Supabase Storage**(保底主力,**可在线听 + 可下载离线**);**视频 YouTube 在线**(不下载,YouTube 条款禁下载);每课双轨,视频失败回退音频;闻思圆满听/看任一即可(音频离线即可完成闻思,视频不下载不影响达标)。
- **媒体 URL 走数据库字段**(lesson_resources/practice_guides 存 url),托管位置可替换——为将来流量增长迁 Cloudflare R2 留门(改配置非重写)。
- **时区四层**:存储 UTC;班级集体按 `cohort.timezone`(IANA);藏历固定 UTC+8;个人打卡跟手机本地。
- **开发**:Claude Code 主力;代码所有权优先;TypeScript 降低 AI 出错。

## 3. 规模与演进(目标 T2)

- **目标 T2**(多班/多租户,几千–几万),为 T3 留门。**技术栈不换**——Expo + Supabase 原生即可支撑 T2。
- **可规模化的关键**:人工关怀单位是"班"(每班约50人配5-8爱心),比例固定可复制;"很多个小班"模式下精神不反规模。
- **T2 友好纪律(现在执行,零成本)**:① 一切数据带维度键 `cohort_id`/`program_id`/时间戳;② 师兄端事务查询限单租户(带 user/cohort 过滤,不全表扫描);③ 事务与分析查询分离;④ 不假设"全局单池";⑤ 基础慢查询监控。
- **演进预案(到点再做)**:Supabase 套餐升级 / 只读副本(报告走副本)/ 连接池 / 缓存 → T3 再上分片、列式分析仓库。
- **媒体/离线**:音频 Supabase Storage(可在线听 + **可下载离线**);视频 YouTube 在线(不下载)。完整离线(打卡数据本地读写同步)不做(弱网+乐观显示+重试)。媒体 URL 走数据库字段,将来流量大迁 R2(零出站费)+ HLS + 原生后台音频 = T3/v2.0。
- **原则**:勿过早为假想规模重构。

# 第三部分:闻思要求

## 6. 闻思(四专业通用)

- 第1学期入门教材(46课);第2-8学期专业课 + 限制性课(大学演讲系列,第2-7学期每学期3册,第1/8学期不安排)。
- **正式课圆满** = 听音视频≥1遍 + 看法本≥1遍 + 思维/作答思考题(三项)。
- **限制性课圆满** = 听≥1遍 + 看≥1遍(**无思考题**,本就不含)。
- **盲/聋豁免**:盲免看法本(听2遍=圆满)、聋免听法(看2遍=圆满)。`accessibility_needs` v1.0 存,**自动判定推 v1.5+,v1.0 人工**。
- 闻思可批量补录(每学期 2 次报数)。

# 第四部分:实修与报数(核心)

## 7. 加行

- 前行实修法 1-92,目标 **276 座 / 138 小时**,逐修法 ≥3座/≥30分(升密法每法 ≥3座/≥1.5h)。
- **座次计数**(回归大纲):
  - 净观修 ≥30分 = 1 座(超过 30 仍 1 座,不可拆)。
  - <30分:按**同一修法**累计碎片,凑满 30 → 1 座,**成座余数清零、不滚存**。
    > 📌 依据(铁律1):大纲仅规定"几座时间合在一起视为一座",**未规定余数如何处理**;"清零不滚存"为产品取舍(避免引入无状态余额表,保持打卡无副作用),记为 explicit decision。
  - **总时间独立**于座次,按 duration 全额累计,不经碎片池。
  - **无 0.5 座**。录入页提示"只填净观修时间,前后念诵不计"。
- **逐修法达标 v1.0 不自动校验**,只存数据(推 v1.5+/毕业人工)。
- **6 内加行各 10 万**(顶礼/皈依/发心/百字明/供曼茶/上师瑜伽):
  - 顶礼只记遍数;**默认含法王祈祷文**(标准修法即边顶礼边念,不单独追踪;极少例外 admin 线下)。
    > 📌 依据(铁律1):大纲规定"顶礼时应念法王祈祷文;未念者应在毕业前补念 10 万遍"。v1.0 **逐修法不自动校验**故合并为"默认含、不单独追踪";**但 v1.5+ 升学评估时,法王祈祷文须作为独立达标口径核对**(大纲明文要求,否则丢失"未念者补念 10 万"这一升密法门槛)。记为 explicit decision,留 v1.5 实现门。
  - 供曼茶须持曼茶盘,打卡页提示(靠自律,不技术拦)。
  - **仪轨合规靠引导非判定**:每修法挂 文字(尽量都有)/视频/音频 三种引导,师兄按正确仪轨修。
- 200 万心咒代顶礼:v1.0 admin 线下。

## 8. 净土

- 念佛号**三选一**(南无阿弥陀佛5000 / 阿弥陀佛7500 / 藏文900):**师兄入学时自己选定、锁定不可换**;目标 = 每日功课量;**每日完成制**打卡(看坚持天数)。

## 9. 入行

- **两条独立修持项**:① 每周 ≥3 座观修(时长不限)② 每天观音心咒 ≥1000 遍。可任选其一或都做,各自打卡。

## 10. 学经

- **固定功课**(auto 愿/每日):心经每天 1-9 遍 + 普贤行愿品每天 1 遍。
- **自选经**:七经选若干,**每部一条 custom 愿**,师兄自定节奏(每天N遍/每周N遍)+ 期限(学期末/自定天数)。抄经拜经同方式,自愿。

## 11. 数据真实性与补录

- **没有记录默认为 0**,系统不臆造。
- **师兄可随时补录往昔真实打卡**:填**实际修持日期(过去或今天,不可未来)**,数据落真实那天,**即时生效、不受审核期限制**。
- **立场:信任师兄**(修行为自己,不为别人)。
- **理由(改了原则6)**:源于闭关师兄依纪律只能纸笔记录、出关后才能录入——闭关是精进非懈怠,旧立场"过去就是0"会误伤。与原则1信任师兄一致。详见《原则6改写补丁》。
- **审核态降级**:从"数据生效关卡"降为辅导员"可选核对工具",不作数据计入前提。

# 第五部分:共修 · 报数 · 关怀 · 报告

## 12. 共修

- **频次**靠辅导员线下掌握(每月≥2次 / 第2学期起每月≥1次实修共修),App 不强制、不催,只记实际共修(用于出勤累计)。
- **普通共修**:每班设每周固定时间 + Zoom 链接(建班设、辅导员/admin 随时改、绑班级时区)。
- **实修共修**:同结构设定预留(v1.0 可空,需要时启用)。共修记录分类型(普通/实修)。
- 网络共修/自学:按既有规则申请。

## 13. 报数

- 每学期 2 次(按学修课表),主动如实完整;**信任师兄,不需他人确认才算数**。
- **虚报处理**:全部线下(谈话/书面忏悔/取消资格),App 只记最终 `status=left`,不做忏悔表单。

## 14. 关怀(人工,不动)

- 4 级状态机(on_track/slightly_behind/falling_behind/at_risk;师兄不可见、管理者可见)→ 爱心 C1 关怀名单 → 电话跟进填 care_followups。
- App **不**依打卡/掉队自动推送催促(原则9)。
- **师兄自设修行提醒**(每日多次,≤20条;师兄→自己的闹钟,非 App 催促)v1.0 做(expo-notifications)。

## 15. 报告与分析

- **两类查询分离**:事务限单租户(快);分析可跨班、走只读副本(慢)。
- **T2 实现**:普通 SQL 聚合,维度键(cohort/program/practice/时间)齐备。
- **口径**:① 默认用全部数据(信任师兄,不分确认态);② 密法(share_to_collective=false)**不进任何聚合报告**;③ 自学师兄单列"自学"维度,不混班际。
- **红线(过原则1/10)**:**仅管理端可见,绝不泄露到师兄端;用于关怀与改进教学,非考核排名。**
- 具体报告清单**暂缓**(框架就位,随时填)。

# 第六部分:学员状态与去向

## 16. 状态与去向

- **状态**:active / paused / held_back(留级) / graduated / left。
- **专业锁定**:专业 = 班级属性;**第一学期内 admin 可改 program(纠错),第二学期后锁定**;师兄无个人专业字段、无权换班。
- **留级**:v1.0 已做(held_back + held_back_count);**次数上限 admin 人工掌握**。
  - **次数上限(2026-05-28 教务确认,补齐学经)**:加行 ≤ 2 次、**学经 ≤ 2 次**、净土 ≤ 1 次、入行 ≤ 1 次。(原大纲第25–26页未列学经,经教务确认学经同加行=2次。)
- **兼修(一人多班,2026-05-28 教务确认)**:
  - 同一师兄可同时在多个**不同专业**班学修,**人数不限**(沿用 D12 口头确认,现教务书面确认)。同专业不同届(如 22加行+23加行)**不允许**。
  - **兼修师兄留级 = 两专业互不干涉,各班完全独立**:某班留级**不影响**另一班(另一班照常继续);两班进度错位**不特别处理**(各班各显示);两班毕业不同步**各自毕业**。与「班级独立、无依赖」原则(D12)一致。
  - ⚠️ 依据凭证:教务原始确认记录需 PM 另存入「教务确认存档」(本条仅记结论)。
- **转菩提功德会**:独立群体(cohort 标记);辅导员/admin 移入(师兄同意);**记录保留**;无强制功课;"回来"机制 v1.0 不做。
- **毕业转预科 / 升学判定**:规则记入文档,**实现推后**(新班约4年后才毕业)。
- **正科转预科**(正科14届转入):暂缓(暂时不会有)。

# 附录 D · 原则 6 新版全文(数据真实性 = 默认0 + 信任补录)

> 替换 principles(`principles_2026-05-31`)原则6全节(✅ 已于本轮落地)。改了最高层原则,触发理由:闭关师兄只能纸笔记录、出关补录;贯彻原则1信任师兄。

**核心**:系统**不臆造**任何修持数据——没有记录默认为 0;同时**信任师兄如实补录往昔真实发生的修持**。真实性来自"空就是空"+"信任师兄诚实",而非"过去不可追补"。

**具体实现**:
- 没有记录默认为 0(空白即0,不填充不估算)。
- 师兄可随时补录往昔真实打卡:输入**实际修持日期**(只能过去或今天,不能未来);数据落真实那天,报告/状态机按真实日期算。
- **补录即生效,不受审核期限制**;审核态只管当前半学期内的新打卡,跨已审期的旧补录直接计入,不强制重审。
- 暂停不顺延due_date;start_date改动不联动历史;共修讲考确认后不能改。

**explicit reasoning**:
- 闭关师兄依纪律只能纸笔记录、出关录入;闭关是精进非懈怠,旧立场"过去就是0"会误伤最用功者;日常无网同理。
- 与原则1一致:信任师兄自报当下,亦信任补录往昔;造假者当下亦可造假,补录不增造假可能。
- 真实性防线转移:从"禁止追补"转为"默认0+信任自报";没修的人不会因开放补录被臆造数据(空仍是0)。

**仍然为0**:师兄确实没修的日子无记录=0(系统不补);App对掉队仍0提示(原则1/9),是否补录由师兄自主,App不催。

**例外/边界**:✅闻思批量补录;✅修持补录(填真实日期);❌不能补未来日期;❌共修/讲考确认后不能改。

**反例(仍违反)**:❌系统自动为掉队师兄估算/填充修量;❌暂停期间自动顺延due_date。

**连带更新**:原则1"掉队0提示"保留(0提示≠强制为0,师兄可自主补录);PRD场景11/§5.14/S10/S11加补录入口;schema practice_logs.log_date 禁未来;验证清单第6条措辞改"臆造"。

**给开发者一句话**:没记=0,系统绝不替补;师兄可补录任意过去日期的真实修量,落真实那天,即时生效。不要实现"修持禁止补打"的旧逻辑。
