## ⚠️ 后端/数据库设计规则（2026-06-13 PM 新增，约束所有后续设计）

1. **设计后端时必须先参考现有结构**：以 `supabase/migrations/`（操作真源）+ 生产库现状为准，理解既有表/函数/RLS/触发器后再设计，**不凭空新建**。
2. **给出最佳方案**：基于现有结构提出方案（含 2-3 个选项+取舍时给选项），优先复用现有表和机制。
3. **需要修改数据库时必须提示 PM**：明确列出"要改什么表/加什么字段/动什么 RLS"，**由 PM 确认之后才能设计**；Claude Code 不可以自行确定设计方案，更不可自行写迁移。
3b. **发现现有设计非最优时同样提示**：若认为现有数据库/后端结构不是最优方案，主动提示 PM 并给出最优方案（含取舍对比），由 PM 确定后再行动。
4. 与既有工作规则衔接：规则8（功能逻辑阶段不做 DB 设计）依然有效——本规则约束的是**进入 DB 设计阶段后**的工作方式。
