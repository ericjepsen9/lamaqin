## v4.0 变更摘要(架构级:课程固定,时间灵活)

⚠️ **这是 v3.9 之后最大的架构改动**。核心思路:**课程内容全局固定(挂班不挂届),时间安排灵活(休息周 + 双模式)**。注:加行专业课 165 节(7 部 course)、全程 211 节(含第1学期入门 46),"144"仅指其中《大圆满前行》一部;权威节号轴见 TERMINOLOGY 1.3。

### 设计原则
1. **课程内容(courses / course_lessons)= 全局固定** — 不绑 cohort,所有班级和自学师兄共用
2. **班级日历 = start_date + cohort_rest_weeks(休息周)** — admin 加休息周记录,算法自动跳过
3. **师兄"本周课程"= 两步(2026-05-26 重设计;v2 2026-06-01 改 (学期号,学期内周),见 schema §12.6.5)** — ① `get_current_week_number` 算有效进度,输出 **(学期号, 学期内周)**(日期 − 计划外休息周;**已删留级回拨**)② `get_week_lessons(program, 学期号, 学期内周)` 查 program_week_courses 得本周节次(支持交错穿插多节);UI 可用便利函数 `get_current_week_lessons` 一次拿全。**非纯算术,须查周映射表**
4. **双模式**:
   - **班级模式**(cohort):跟班学习,有 cohort.start_date + 班级休息周 + 共修/讲考/公告
   - **自学模式**(self_study):完全独立,无 cohort,无共修/讲考/公告/辅导员关怀;有个人 start_date + 个人休息周
5. **混合模式**(both):师兄可同时跟班(如加行)+ 自学其他系(如入行)

### 主要 schema 改动
- **新增 3 张表**(表数 40 → **43**):
  - `cohort_rest_weeks`(班级休息周)
  - `user_self_study_rest_weeks`(自学师兄个人休息周)
  - `user_self_study_programs`(自学师兄的科系记录:start_date + status + pace)
- **profiles 加字段** `learning_mode text DEFAULT 'class'` CHECK IN ('class','self_study','both')
- **进度函数**(v2 2026-06-01 定稿,见 schema §12.6.5):`get_current_week_number(user, program, today)` → (学期号, 学期内周) / `get_week_lessons(program, 学期号, 学期内周)` / `get_current_week_lessons(user, program, today)` 合并。~~旧 `get_current_lesson_number` 已废弃删除~~
  - ⚠️ 自学表校对修正:加行周次↔节次为**多对多**(第2学期开显与前行广释并行、第8学期4部并行收尾),
    且须覆盖**第1学期入门46节**;算法不可假设"全局连续序号",须查 program_weeks 逐周映射(样本见 schema §13.3f)。
- **修订** `program_weeks` 表语义:从"具体日历"降级为"课程内容序号 + 元数据"(因为日历由算法实时算)

### 撤回的 v3.9 决定

- ⚠️ **场景 18 尾巴** program_week_practices 表 — 字段语义改成"课程内容序号对应",不再是"日历周对应"

### 修订的 v3.9 决定

## 1.5 产品哲学(v4.1 更新 · 三殊胜总纲 + 13 条核心原则 + 双模式)

**从 21 场景走查 + v4.0 架构改动中提炼**,作为验证未来所有新决定的统一标准。详见独立文档 `principles_2026-05-31.md`。

### 0 · 三殊胜:精神总纲(v4.1 新 · 最高准绳,#179-180)

App 之名「三殊胜」即其灵魂,是贯穿整个 App 的精神骨架;下方 13 条产品哲学皆可视为它的展开。任何决定先过三殊胜,再过 13 条。

| 殊胜 | 含义 | App 体现 |
|---|---|---|
| **前行 · 发心殊胜** | 做事前发起正确的心(为利众生) | 「发心」Tab;打卡/学修前一句轻量发心语(可关);集体回向的共同发心 |
| **正行 · 无缘殊胜** | 修的当下无执著、不攀缘、安住 | **克制即体现**:不催不扰、不排名、隐藏总累计目标、师兄端无状态色、不推送 |
| **结行 · 回向殊胜** | 做完把功德回向一切众生 | 打卡收尾轻量回向(可选);「功德回向」(累计修量=可回向功德);集体回向(法会+每周);日记后可回向 |

**两个关键洞察**:① 正行无缘 ≈ App 既有的所有克制(隐藏总目标/无状态色/不排名/不推送),在三殊胜下找到统一源头;② 功德回向不破"隐藏总累计目标"——隐藏的是"还差多少达标"(生压力),展示的是"已积累多少可回向"(正向)。
**v1.0 落地**:精神与调性层面轻量贯穿,**不做**"发心→正行→回向"强制三段表单(违原则 1/2)。详见 principles_2026-05-31.md 第 0 条。

### 核心 13 条

| # | 原则 | 一句话 |
|---|---|---|
| 1 | **信任师兄,App 是工具不是教练** | 不催、不评判、不强制 |
| 2 | **v1.0 减法优先** | 不做"申请-审批"流程 |
| 3 | **admin/辅导员直接操作 > 师兄申请** | 管理动作走后台不走流程 |
| 4 | **节奏自主,无审批** | 师兄改起修日/节奏/暂停不审批 |
| 5 | **班级集体 vs 个人 区分对待** | 听/讲/共修 = 集体;思考题/修行 = 个人 |
| 6 | **数据真实性 > 用户体验** | 不能事后补造修持数据 |

### v4.0 新增设计原则:课程固定,时间灵活

**核心理念**:把"课程内容"和"日历时间"解耦。

- 课程内容(courses / course_lessons)= 全局固定,所有班级和自学师兄共用
- 班级日历 = start_date + 休息周记录(算法自动跳过)
- "本周课程"= 有效周(算)+ 周→节映射(查 program_week_courses);课程内容与日历解耦(原则13),映射表由 admin 录入(ROADMAP C6)

- 整学期推迟 1 周 = 加 1 条休息周记录(不再需要批量改 50+ 条数据)
- 自学师兄完全独立运行,无需依附 cohort
- "推迟"和"恢复"对称简单(加休息周/删休息周)
- 师兄个人节奏自主(自学模式可自定休息周)

**这跟原则 8(修行愿跟日历无关)更彻底统一** — 现在连**闻思日历**也跟日历有了自主权。

# §2 · 业务模型

## 2.1 组织结构(v4.1 纠正 · 学会 → 班 → 届)

```
学会(整个佛学会 = 所有师兄)          ← "全会" 指这一层(每周回向全会层)
  │
  ├── 班(核心单位:基础 / 加行 / 净土 / 入行 / 学经 / 中观 / 密法 …)
  │     │     · 科系标签(以后加,不单独建层):预科系 / 正科
  │     ├── 课程体系(全局固定,不绑届 — 原则 13)
  │     ├── 8 学期 × 26 周 排表模板
  │     └── 修持模板库(推荐给班级)
  │
  └── 届 / 年次(COHORT:22届、23届…;统一用「届」不用「级」)
        ├── 起始日期(决定每周实际日历日期)
        ├── 班级管理员(辅导员 + 爱心师兄)
        ├── 学员(师兄们)、班级公告
        └── 班级 ↔ 模板绑定(哪些是 auto)
```

⚠️ **v4.1 纠正**:
- 「级」全局统一为「**届**」(22届,不用"22级")。
- **正科不是一个班 / 不是与加行平级的专业**,而是**科系标签**(下辖中观班/密法班);预科系标签下辖 基础/加行/净土/入行/学经。科系作**标签**处理,不单独建组织层(原则 2 减法);需筛选时按标签过滤。
- 「班」歧义:口语"加行班"指内容(加行);系统里一个**具体班 = 班 × 届**(如"22届加行班")。auto 愿绑具体班(届);custom 愿不绑。

**原则:班级独立、无依赖、无项目顺序约束**。师兄可加入任意班、任意顺序、多班并行。常见路径(参考、不强制):基础 → 入行/加行/净土/学经 → 正科(科系)。

## 2.2 多班并行规则

- 师兄可**同时**加入多个 cohort
    - 例:张师兄 = "22 加行班学员" + "23 入行班学员"
- 默认有一个"主班"作为 dashboard 优先视图
- 学修记录、修持愿都按 cohort 独立归属

## 2.3 各班修持要求对照

| 班 | 主体闻思课程 | 班级 auto 模板 |

| **净土班** | 阿弥陀经 + 普贤行愿品 + 亲友书 + 藏传净土法 + 修心利刃轮 + 愿海精髓 | "南无阿弥陀佛" 5000/天,或"阿弥陀佛" 7500/天,或藏文 900/天(三选一) |

## 2.4 修持哲学(核心)

### 两种修持愿来源(v4.1 · 3→2,event 降为标签)

```
1. 班级愿(source='auto',建议必修)
   - 加入班级时自动按模板绑定
   - 项目/总数/周期 锁定,节奏可调(原则 4)
   - 师兄不能删除,没修完面临留级

2. 自发愿(source='custom')
   - 完全自定义(项目/总数/周期/节奏全可选)
   - 必填截止日或选"终生"
   - 师兄自己负责,可随时删除

※ 法会回向(event)不再是第三种愿,降为正交可选标签 event_id:
   任何愿(auto 或 custom)都可挂 event_id 参与法会回向。

※ 约修(v4.1 新):师兄发起共修、他人加入 = 系统为各人建一条 custom 愿
   (appointment_id 指向约修),打卡/累计走现成愿系统。详见 §4 同修 Tab。

※ 班级 recommended 模板 — 暂不做(v1.5+);v1.0 辅导员用 WhatsApp 通知,师兄自己 custom 加。
```

### 节奏自主原则

- **节奏由师兄自选**(admin 不强加)
- **改节奏无需审批**(v3.7 场景 1) — 师兄自己改 daily_target / weekly_target / start_date,记 pace_history
- **三种交互方式**:默认 / 自由调 / 反向算
- **soft warning 不 hard stop**
- **状态隐私**:师兄端不显示状态颜色;只有辅导员/爱心/admin 看完整状态

### 关怀代替惩罚

- 系统不阻止师兄做选择
- 状态自动改变(on_track → at_risk)— 师兄看不到,只有管理者看
- 爱心师兄看到 → 主动电话关怀
- 辅导员线下沟通后**直接改 due_date**,trigger 自动写 audit_logs
- v1.0:上师金刚语提示已落地为修行提醒预设语库(reminder_presets,#188,只放可公开教言);游戏化机制仍 v1.5+

## 4.0 师兄端导航架构(v4.1 · 4 Tab · #175-178)

师兄端底部导航定为 **4 Tab**:`当日 / 同修 / 发心 / 末学`(取代旧 5 Tab 设想)。

| Tab | 代号 | 定位 |
|---|---|---|
| **当日** | Home | 本周学修次第(闻→思→修)+ 共修讲考时间 + 日历 + 打卡 + 殊胜日 banner |
| **同修** | Community | 集体回向(法会+每周)+ 约修 + 班级公告 |
| **发心** | Aspiration | 利他·为众生(发心引导 + 管理者照顾班级) |
| **末学** | Me | 自利·学员自管学修 + 修行 + 功德回向 + 设定 + admin |

**核心依据**:
- **闻思修有次第,无闻思盲修**(#175)→「修」不独立成 Tab(避免暗示可绕过闻思直接修),嵌入「当日」次第;其配置(修行/愿)归「末学」,集体部分(集体回向/约修)归「同修」。

- **「发心」一词三义统一**(#178):前行发心(调心)/ 发心工作(承担)/ 为众生即菩提心,良性多义,UI 靠语境区分。

## 5.2 多班并行(v3.9 场景 10 扩展)

**加入多班的方式**:
- 注册时选 1 个班(场景 9 自助注册)
- 注册后任意时点,在 S4 屏点"+ 加入新班"自助加入(v3.9 场景 10.1)
- 无班级数量上限;加第 4 个时建议加软提示

**加新班流程**(v3.9 场景 10.1):
1. S4 屏选科系 + 选届(下拉只列 `cohort.status='active'` 的班)
2. 弹窗 1:**是否在该班修持?**
   - "完整学修" → 系统按 cohort auto 模板建愿
   - "仅闻思" → 跳过所有 auto 愿,师兄只听课/答题/共修

6. v1.0 **不查愿冲突**,允许同师兄多条同 practice_id 的 active vow(辅导员线下提醒)

**主班(`is_primary = true`)**:
- 每师兄只有 1 个主班(UNIQUE 索引 `uniq_class_members_primary` 保证)
- 默认跳转、默认排序的优先班级
- UI **跟辅班一视同仁**,不代表"重要程度",仅在默认跳转优先
- 学修记录、修持愿按 cohort 独立(`user_practice_vows.cohort_id` 允许 NULL,v3.7 场景 8)

**换主班**(v3.9 场景 10.2):
- 师兄**不能自助**切;线下联系 admin 或辅导员
- admin + 任意辅导员(C1 宽松)都能改任何师兄的主班

### 5.8.1 模板的两种来源

### 5.8.2 start_date + offset 机制(v3.7 场景 1 + v3.9 场景 18 修订)

```
模板里存:
  starts_offset_days     距 cohort.start_date 多少天起修
  duration_days          起修后多少天完成
  default_daily_target   每天目标

师兄实例化时(加班自动):
  start_date       = cohort.start_date + starts_offset_days
  current_end_date = start_date + duration_days
  daily_target     = 模板拷贝
```

**好处**:
- 一个模板服务所有届(19/20/22/26 级共用)
- M4 排表导入时按 offset 算 program_weeks / group_sessions / speaking_sessions 的初始日期
- custom 愿不受影响

⚠️ **v3.9 场景 18 修订**:
- **撤回**原 v3.7 场景 1 的 `cohort_start_date_change_trigger`
- start_date 改动**不自动联动**任何下游(user_practice_vows / program_weeks / group_sessions / speaking_sessions 都不动)
- offset 机制**只用于初次建愿和 M4 排表导入**算初始日期
- ~~整学期推后 → admin 在 **M4 屏使用"批量调整未来日期"**~~ **v4.0 撤回**:改用 M9 屏管理 cohort_rest_weeks(加 1 条休息周记录,算法自动跳过)
- 修行愿(user_practice_vows)按个人累计目标算,本来跟日历无关,完全不受影响
- 辅导员想给个别师兄宽限 → 在 A3 屏直接改 current_end_date(场景 6 机制)

⚠️ **v4.0 进一步修订**(详见 §5.15):
- 课程内容(courses/course_lessons)全局固定,跟班级无关

| 师兄 | ❌ **完全看不到状态颜色/标签/警示**,只看数字 |
| 师兄 | ❌ **隐藏总累计目标**(v3.7 场景 6:避免压力);只看日/周节奏 |
| 辅导员/爱心/admin | ✅ 完整状态机 + 关怀名单 |

### 5.9.2 状态枚举(v3.7 场景 6:8 → 7 种)

```
on_track          - 🟢 顺利
slightly_behind   - 🟡 略落后
falling_behind    - 🟠 明显落后
at_risk           - 🔴 严重落后
will_overdue      - ⚠️ 将超期
completed         - ✅ 已完成
paused            - ⏸️ 暂停中

❌ 删除 'in_grace'(辅导员直接改 due_date 后状态机按新日期重算,不需要中间状态)
```

### 5.9.3 计算算法(3 套)

**前置判断**(v3.9 场景 13):
```
if vow.status != 'active':
    return  # paused / completed / abandoned 都不算 current_status
```

只有 `vow.status='active'` 才进入下面 3 套算法。

#### 算法 A · weekly 类(如 92 修法每周 4 座)

```
状态指标:连续未达标周数(从最近往前数)
本周不参与判定(进行中)

0 周未达标 → on_track
1 周           → slightly_behind
2-3 周         → falling_behind
≥4 周          → at_risk
```

#### 算法 B · daily 类(如百字明每天 200,终身)

```
状态指标:近 15 天达标天数

≥13 天(≥87%) → on_track
11-12 天       → slightly_behind
8-10 天        → falling_behind
<8 天          → at_risk
```

#### 算法 C · 有 total_target + end_date 类(如顶礼 10 万,2 年)

**两套并存,取更严重**:
- C1 累计维度: 应完成 = total_target × (today-start)/(end-start);看完成比
- C2 持续性维度: 用算法 A 或 B

### 5.9.4 起修豁免

起修后 7 天内,任何愿强制 on_track。

### 5.9.5 触发计算时机

- 师兄打卡后立即重算该愿
- 周日凌晨 cron 全平台重算(把上周封盘)
- **辅导员改 due_date** → 立即重算(v3.7 场景 6,trigger 自动写 audit_logs)

### 5.9.6 关怀名单排序(v3.7 场景 6:删 in_grace 条目)

- at_risk 愿数量(多的优先)
- falling_behind 愿数量
- 上次关怀时间(久的优先)

#### 成员范围(2026-05-28 补 · T1)

名单按 cohort 分组生成。每位师兄的 at_risk / falling_behind 计数,**仅统计该 cohort 下 `source='auto'` 且 `status='active'` 的愿**。
`source='custom'` 的自发愿、以及 `cohort_id IS NULL` 的个人愿,**不计入任何班级关怀名单**(custom 对管理者私密 + 自愿项荒废非掉队,守原则1克制)。
兼修师兄在各班的计数互相独立,互不影响。

> **核查依据(T1)**:`current_status` 是 `user_practice_vows` 上的逐愿字段(每条带 cohort_id),算法逐愿计算 → 兼修师兄两班状态天生各算各的,「某班荒废传染另一班」在状态机层不可能发生;爱心端 RLS 按 `has_class_role(cohort_id,['zhumai','aixin'])` 只能读本班愿,再兜一道。详见 architecture_decisions 八-补(续)。

## 5.15 双模式与休息周机制(v4.0 架构核心)

**核心理念**:课程内容固定,时间安排灵活。

### 5.15.1 课程内容(全局固定)

```
courses / course_lessons 表 = 全局共享
  ├─ 加行系:7 部 course/专业课 165 节(《大圆满前行》144 为其中最大一部);全程含入门 46 = 211
  ├─ 入行系:N 课
  ├─ 净土系:N 课
  └─ ... 6 系

所有班级 + 自学师兄共用这份内容
```

### 5.15.2 班级模式(class)

**数据来源**:
- `cohorts.start_date` — 班级开始日期(由 admin 在 M1 设)
- `cohort_rest_weeks` — 班级休息周记录(admin 在 M9 加/删)

**算"本周第 N 课"**:
```
total_weeks_since_start = (today - cohort.start_date) / 7 + 1
rest_weeks_count = count(cohort_rest_weeks where rest_start_date <= today)
current_lesson_number = total_weeks_since_start - rest_weeks_count
```

**典型流程**:
1. 班级 1 月 5 日开课
2. 师兄按周顺序学:第 1 周第 1 课,第 2 周第 2 课,...
3. 2 月 9 日那周法会 → admin 在 M9 加休息周
4. 算法自动跳过 — 2 月 9 日那周师兄看到的还是上周课(休息)
5. 2 月 16 日 = 第 6 周但跳过 1 周休息 = **第 5 课**

### 5.15.3 自学模式(self_study)

**数据来源**:
- `user_self_study_programs` — 师兄自学的科系记录
  - user_id + program_id + start_date + status(active/paused/completed/abandoned)+ pace_level
- `user_self_study_rest_weeks` — 师兄个人休息周

**师兄端体验**:
- S1 注册时选择"自学模式"
- 选科系(加行/入行/净土/学经/正科/基础)
- 选起修日(默认今天)
- S6 周任务页显示"本周第 N 课"(基于个人 start_date + 休息周算)
- S19 屏管理个人休息周(自定)

**不能做**:
- ❌ 共修(无班级 group_sessions)
- ❌ 讲考(无班级 speaking_sessions)
- ❌ 班级公告(无 cohort)
- ❌ 辅导员关怀(无辅导员)

**能做**:
- ✅ 听课打卡(study_records,通过 lesson_id 关联课程内容)
- ✅ 思考题作答(question_responses)
- ✅ 修持打卡(practice_logs)
- ✅ 修行愿(user_practice_vows,跟班级师兄一样)

**admin 看**:
- M10 屏全局看所有自学师兄列表 + 进度 + 状态
- admin 可改师兄 status(类似辅导员改班级师兄状态)

### 5.15.4 混合模式(both)

师兄可同时:
- 跟班级 25 加行(class_members 表关联 cohort)
- 自学入行(user_self_study_programs 表关联 program)

两套数据独立,互不影响。

### 5.15.5 加入休息周时的影响

**加 1 条 `cohort_rest_weeks` 记录**:
- 全班所有师兄的"本周第 N 课"算法自动跳过该周
- 历史打卡记录不动(study_records / practice_logs 跟 lesson_id 绑,不跟周次绑)
- 共修/讲考有具体日期(group_sessions / speaking_sessions),admin 需在 A8 屏单独调整(不联动)

**删 1 条 `cohort_rest_weeks` 记录**:
- 全班所有师兄的"本周第 N 课"算法不再跳过 → 全班顺延 1 周
- 历史打卡不动

### 5.15.6 v3.9 → v4.0 撤回 / 修订清单

## 7.5 注册流程 Trigger + 函数(v3.9 场景 9)

```sql
-- Trigger 1:auth.users 新建时,自动建 profile(自助注册路径)
CREATE OR REPLACE FUNCTION handle_new_auth_user()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  INSERT INTO profiles (id, email, status, data_source)
  VALUES (NEW.id, NEW.email, 'active', 'self_register');
  RETURN NEW;
END $$;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_auth_user();

-- Trigger 2:profiles INSERT 时,自动生成 student_id(若未传入)
CREATE OR REPLACE FUNCTION generate_student_id()
RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE
  current_year int := EXTRACT(YEAR FROM now())::int;
  next_seq int;
BEGIN
  IF NEW.student_id IS NOT NULL THEN
    -- 导入路径已有 student_id(沿用 Sheets 老学号)
    RETURN NEW;
  END IF;

  SELECT COALESCE(MAX(
    NULLIF(substring(student_id FROM 5), '')::int
  ), 0) + 1
  INTO next_seq
  FROM profiles
  WHERE student_id ~ ('^' || current_year::text || '\d+$');

  NEW.student_id := current_year::text || lpad(next_seq::text, 3, '0');
  RETURN NEW;
END $$;

CREATE TRIGGER profiles_generate_student_id
  BEFORE INSERT ON profiles
  FOR EACH ROW EXECUTE FUNCTION generate_student_id();

-- 函数:师兄自助注册时把自己加进班级(class_members_insert RLS 主策略仍仅 admin)
CREATE OR REPLACE FUNCTION self_register_class_member(
  p_cohort_id uuid,
  p_is_primary boolean DEFAULT true
) RETURNS class_members LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
  result class_members;
  target_cohort cohorts;
BEGIN
  SELECT * INTO target_cohort FROM cohorts WHERE id = p_cohort_id;
  IF NOT FOUND THEN
    RAISE EXCEPTION 'Cohort not found';
  END IF;
  -- 未来可扩:招生期、班级容量等校验

  INSERT INTO class_members (cohort_id, user_id, status, is_primary)
  VALUES (p_cohort_id, auth.uid(), 'active', p_is_primary)
  RETURNING * INTO result;
  RETURN result;
END $$;

-- 老学员植入(M8 屏):走 service_role,完全绕过 RLS
-- 由 Supabase Edge Function 或后端服务实现,前端不能直接用 service_role


-- 12.6.4 切换主班(v3.9 场景 10.2)
-- 师兄不能自助;admin + 任意辅导员(C1 宽松)都能改任何师兄的主班
-- 事务内两步切换,避免违反 uniq_class_members_primary UNIQUE 索引
-- 自动写 audit_logs(跨班操作需追溯)
CREATE OR REPLACE FUNCTION switch_primary_cohort(
  p_user_id uuid,
  p_new_primary_cohort_id uuid
) RETURNS class_members LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
  caller_id uuid := auth.uid();
  result class_members;
BEGIN
  -- 权限校验
  IF NOT (
    is_system_admin()
    OR EXISTS (
      SELECT 1 FROM class_admins
      WHERE user_id = caller_id AND role = 'zhumai'
    )
  ) THEN
    RAISE EXCEPTION 'Permission denied: only admin or zhumai can switch primary cohort';
  END IF;

  -- 目标 cohort 必须是该师兄已加入且 active 的班
  IF NOT EXISTS (
    SELECT 1 FROM class_members
    WHERE user_id = p_user_id
      AND cohort_id = p_new_primary_cohort_id
      AND status = 'active'
  ) THEN
    RAISE EXCEPTION 'User % is not active in cohort %', p_user_id, p_new_primary_cohort_id;
  END IF;

  -- 事务内两步切换
  UPDATE class_members SET is_primary = false
    WHERE user_id = p_user_id AND is_primary = true;
  UPDATE class_members SET is_primary = true
    WHERE user_id = p_user_id AND cohort_id = p_new_primary_cohort_id
    RETURNING * INTO result;

  -- audit log
  INSERT INTO audit_logs (user_id, action, target_type, target_id, metadata)
  VALUES (caller_id, 'switch_primary_cohort', 'class_members', result.cohort_id,
    jsonb_build_object('subject_user_id', p_user_id,
                       'new_primary_cohort', p_new_primary_cohort_id));

  RETURN result;
END $$;
```

⚠️ **并发风险**:student_id 自动生成在并发注册时可能撞车(同一秒同年份),UNIQUE 约束会拦,前端需要重试机制。v1.0 用 trigger 实现,v1.5+ 若并发量大可改用 PostgreSQL sequence(每年一个)。

# §14 · v1.0 补充决议(2026-05-25)

> 本节集中承载本轮新增/补充决策;与《最终需求文档》一致,后者为单一事实源。

## 14.1 报告与分析能力(§6.5 等价)
- **两类查询分离**:事务型(师兄端日常,限单租户、要快)与分析型(报告/跨班对比,走只读副本、可慢)分开。
- **T2 实现**:普通 SQL 聚合;维度键(cohort_id/program_id/practice/时间戳)齐备。
- **口径**:① 默认用师兄输入的**全部数据**(信任师兄,不分确认态);② 密法(share_to_collective=false)**不进任何聚合报告**;③ 自学师兄单列"自学"维度,不混班际对比。
- **红线(过原则1/10)**:报告**仅管理端可见,绝不泄露到师兄端;用于关怀与改进教学,非考核排名**。
- 具体报告清单暂缓(框架就位,后续填)。

## 14.2 专业(科系)锁定
- 专业=**班级属性**(开班设定 program),师兄经加入班级确定专业、无个人专业字段、无权换班。
- **第一学期内** admin 可改班级 program(纠正建班错误);**进入第二学期后锁定**(守大纲"第二学期不得调整专业")。应用层校验(基于学期进度)。

## 14.3 转菩提功德会
- 功德会=App 内**独立群体**(cohort `is_gongdehui` 标记)。
- 辅导员/admin 把师兄从原班移出→移入功德会(师兄同意);**原学修记录保留**(守"不离开团体");无强制功课;"回来"机制 v1.0 不做。

## 14.4 共修设定与频次
- **频次**靠辅导员线下掌握(每月≥2次/第2学期起每月≥1次实修共修),App 不强制不催,只记实际共修(出勤累计 v1.0 已有)。
- **普通共修**:每班设每周固定时间(cohort.weekly_cosession_dow/time)+ Zoom(cosession_zoom_url),建班设、辅导员/admin 随时改、绑班级时区。
- **实修共修**:同结构字段(practice_cosession_*)预留,v1.0 可空,需要时启用。group_sessions.cosession_type 区分普通/实修。

## 14.5 限制性课程圆满
- 限制性课(大学演讲系列)圆满=听≥1遍+看≥1遍,**不含思考题**(限制性课本就无思考题)。区别于正式课的"听+看+思考题"三项。

## 14.6 思考题参考答案(确认)
- 参考答案**全局统一,仅 admin 能改**;辅导员/师兄**只读**(§3.2 已一致)。

## 14.7 虚报 + v1.0 不做项
- 虚报处理**全部线下**(谈话/书面忏悔/取消资格),App 只记最终 status=left,不做忏悔表单。
- **v1.0 不做**:法义答疑通道、反馈/监事会通道、师兄互看他人进度(违三殊胜,否决)。
- **暂缓**:正科转预科继承、毕业转预科继承(实现推后,新班约4年后才毕业)、留级次数上限(admin人工掌握)。

## 14.8 资料托管(v1.0)
- 音频 Supabase Storage(可在线听 + **可下载离线**);视频 YouTube 在线(不下载);媒体 URL 走数据库字段(为将来迁 R2 留门)。
