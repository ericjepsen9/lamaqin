## 决策草案(待中枢编号)· 法会带逐场日程,纯排期不记出勤

**日期**:2026-06-30 ｜ **提出者**:PM ｜ **落地**:App Claude

**背景**:法会持续多天、**每天场次不固定**(逐天可不同),需"**按场排进时间轴** + (后续)**按场推送提醒**"。原**决策140**当时只评估"平台共修要不要记出勤"(结论:不记、不改 DB),**未涉及"结构化日程"需求**;模式字段(每天固定 N 场)也不适用(场次逐天不同)。

**决定**:
1. 法会(`events`)下新增 **`event_sessions`**(逐场行:`session_date` / `start_time` / `title` 场次名 / `mode` 线上·线下·混合 / `online_url` / `location` / `display_order`)。**全平台可见、纯排期、不记出勤**。
2. 学员端「共修 / 法会」**时间轴**:法会有场次 → **每场一节点**(轻·点开进详情发愿/回向);无场次 → **窗口节点**(胖·我已念 / 全平台 + 发愿钮);与本班共修(`group_sessions`)**按时间混排**。
3. 后台「法会管理」→ 每个法会「**管理场次**」**逐场增删**(每天几场不限)。新建法会保持简单(名称/类型/起止/说明),场次另管。
4. **推送(按场提醒)= 后续独立件**:App 现无推送基础设施;先不做,待单独评估(本地提醒〔师兄自设·S23/#188〕 vs 系统按场推;推送对象=全平台/已发愿者)。

**与既有决策关系**:
- **决策140**:本决策在"**法会日程**"范围**覆盖 140 的「不做平台级场次 / 不改 DB」两条款**;但**守住 140 的核心——不记逐人出勤**(`event_sessions` 无任何出勤字段)。
- **决策182 / #193**:集体回向仍**只出总和**(`v_event_dedication_totals`)、**不具名**;场次不引入出勤。✅ 守。
- **决策164 + 时间轴**:共修/法会改**时间轴版式**(**覆盖早先「共修/法会维持卡片布局、时间轴只给班级」的设想**·见 design_v2_decisions 线1414),系 PM 本会话主动反复迭代确认。
- **决策173**:已撤「不推送催促」红线 → 将来"按场推送"在设计上**不被否决**(仍属独立功能,需另立)。

**守**:师兄端**无状态色**;**密法 0 痕迹**;`event_sessions` 写=admin、读=is_active(随 events)或 admin。
