## 一、加行 · 计数判例

### JX-1 ★ 单笔满 30 分钟记 1 座，超时不拆
单笔净观修时长 ≥ 30 分钟，自动记为 1 座；超过 30 分钟仍然只记 1 座，不可拆成多座。
（出处：requirements_master §7 行113；schema §12.3 行1913+1927；feature_inventory_v2 5.9 行144，决策093/#189+048）
> 📌 PD-2 裁决（2026-07-04）后口径更新：「30 分钟」= 愿的默认门槛；实际按该愿 `min_session_minutes` 的**打卡时刻快照**判座，改配置不追溯历史。判例中固定写 30 的场景均指默认配置下。

### JX-2 ★ 不足 30 分钟记 0 座，永不产生 0.5 座
单笔净观修 < 30 分钟，自动记 0 座，不单独成座；系统绝不产生 0.5 座。
（出处：requirements_master §7 行113-114 + 决定#189 行273「大纲无半座；1座=满30分钟」；schema §12.3 行1913+1916；prd 行428+481）

### JX-3 ★ 总时间独立全额累计，不受座次影响
总修持时间按 duration_minutes 全额累计到进度里，独立于座次判定：即使这一笔记 0 座，它的分钟数照样全额计入总时间。
（出处：requirements_master §7 行116；schema §12.3 行1916 + §12.2 trigger 行1878-1900；prd 行428+481）

### JX-4 ★ 放弃短座合并：零散不足 30 分钟各记 0 座，不合并、不滚存（比大纲更严）
零散不足 30 分钟的记录各记 0 座，系统**不提供**「把几座短时间拼成一座报数」的功能，也不跨记录自动凑碎片。
（出处：大纲行110-112；requirements_master §7 行114-115；schema §12.3 行1914-1915；符合性验收报告 §四 DR-91）
> ⚠️ **有意偏离大纲**：大纲行110-111 明确**允许**「不满30分钟可几座合并视为一座报数」，但产品 DR-91 决定放弃这一便利、比大纲更严（每座下界 30 分、废 0.5 座、避免引入余额/碎片池）。requirements_master §7 与觉学设计线两处一致。**PM 已确认沿用（2026-07-04，见 PD-1 裁决）**；建议向教务报备此偏离留痕。

### JX-5 ★ 成座后余数清零、不滚存
一条记录成座后多出的时间一律清零、不滚存，不留去凑下一座（系统无余额表）。例：一条 50 分钟记 1 座，多出的 20 分钟不留存。
（出处：requirements_master §7 行114-115，铁律1注；schema §12.3 行1917；feature_inventory_v2 5.9 行144）

### JX-6 ★ 编辑打卡改时长后按新时长重判座次
师兄编辑打卡改动了修持时长时，系统按新时长重判座次并同步修正进度（先减旧座数、再加新座数）。只改反思、不改时长时不重算座次。**重算所用门槛 = 该条记录的快照门槛（PD-2 裁决），不是愿的当前配置。**
（出处：schema §12.3 行1924+1928-1929；§12.2 行1890-1894；prd 行1015+428）
- 边界：把 20 分钟改成 35 分钟，座次 0→1；把 40 分钟改成 25 分钟，座次 1→0，进度相应减 1。
- 边界：改/删仅在「未审核」状态下允许，审核锁定后师兄不可改（prd §5.10.2 行995）。

### JX-7 一笔打卡严格只归属一条愿
一条打卡记录必须严格归属唯一一个愿，不允许多归属；打卡界面强制师兄选愿，一笔只记一处。
（出处：prd §5.10.1 行979-983；feature_inventory_v2 5.7 行142，决策093；schema practice_logs 结构）
- 边界：同一次修持同时对应多个愿时，师兄需选记到哪条愿，不双计。

### JX-8 同日同愿可多次打卡、自动累加
同一天对同一条愿可以多次打卡，每次都单独记一条并自动累加。
（出处：prd §5.10.2 行985-987；feature_inventory_v2 5.7 行142，决策093；schema §12.2 trigger 行1878-1900）
- 边界：同日两条各 30 分钟 → 座次 +2、时间 +60。
- 边界：同日两条各 15 分钟 → 座次 +0（不自动凑成 1 座，须师兄自行合并）。

### JX-9 ★ 逐修法达标 v1.0 只存数据、不自动校验
逐修法达标口径为每法 ≥3 座 / ≥30 分（升密法每法 ≥3 座 / ≥1.5 小时），但 v1.0 不自动校验，只存数据，达标判定推到 v1.5+ 或毕业人工核对。
（出处：requirements_master §7 行111 + 行118；prd 行428）
- 边界：v1.0 只需验证「数据存下来了」，不验证「每法是否达 3 座」。
- 边界：整体目标 276 座 / 138 小时属聚合口径，同样 v1.0 不做达标拦截。

### JX-10 顶礼按遍数计，不计座次
顶礼类按遍数计（单位「遍」），不计座次；目标 10 万遍。
（出处：requirements_master §7 行119-120；schema 种子 行2551；prd 行483+421）
- 边界：顶礼默认含法王祈祷文，不单独追踪遍数；v1.5+ 升学评估须把法王祈祷文作为独立达标口径核对（requirements_master §7 行120-121）。
- 边界：200 万心咒代 10 万顶礼，v1.0 走 admin 线下，不做自动代修联动（requirements_master 行124；prd §5.10.5 行1037-1047）。

### JX-11 六内加行除顶礼外均按遍数计，供曼扎持盘靠自律
六内加行中除顶礼外（皈依 / 发心 / 百字明 / 供曼扎 / 莲师心咒）均按遍数计，各目标 10 万遍；供曼扎须持盘仅在打卡页提示、靠自律，不做技术拦截、不计座次。
（出处：requirements_master §7 行119+122；schema 种子 行2552-2556；feature_inventory_v2 5.10 行145）

### JX-12 座次类修法（含 92 修法、上师瑜伽）一律按时长判座
按座次计的修法（92 修法、上师瑜伽等）其座次一律按时长判定（≥30 分 = 1 座）。
（出处：schema 种子 行2557-2558；行2588-2590；prd 行481-482）
- 边界：寂止修（禅修）同样座次 + 时长（prd 行482）。
- 边界：92 修法打卡必须选第几法，但选哪一法不影响座次算法（prd §5.10.3 行1008）。

## 二、净土 · 计数判例

### JT-1 念佛号功课三选一，不可自填第四种
净土师兄的念佛号功课必须从三个预设中三选一：南无阿弥陀佛 5000/天、阿弥陀佛 7500/天、藏文名号 900/天；没有第四种，也不可自填其它数量。
（出处：requirements_master §8 行128；prd 行429 及班级表行422；schema §13.6 行2578-2582）
- 边界：三个选项对应同一「阿弥陀佛号」功课，单位「声」，仅每日目标不同（5000/7500/900），均为每日型（schema §13.4 行2560、行2579-2581）。

### JT-2 三选一入学时自选、选定后锁定不可换
三选一在师兄入学时由本人选定，选定后锁定不可换。
（出处：requirements_master §8 行128；prd 行429；schema §13.6 行2578+2582；feature_inventory_v2 5.11 行146）

### JT-3 ★ 目标口径 = 每日功课量，不是终生累计总目标
净土念佛号的目标是「每天该念多少」，不是一个终生累计的总数目标。
（出处：requirements_master §8 行128；prd 行429；schema §13.6 行2579-2581，target_period='daily'）

### JT-4 ★ 每日完成制打卡，考核坚持天数
念佛号采用「每日完成制」：判断的是每一天有没有完成当天功课量，考核维度是坚持天数，而不是历史累计总声数。
（出处：requirements_master §8 行128；prd 行429；schema §13.6 行2582；feature_inventory_v2 5.11 行146）
- 注：「坚持天数」的具体算法/达标窗口净土节未给公式，见待裁决 PD-8。

### JT-5 ★ 某天当日累计 ≥ 当日目标即判该天完成
达标口径：某一天的当日累计念佛数 ≥ 当日目标（所选的 5000/7500/900），即判该天完成。
（出处：feature_inventory_v2 5.11 行146，决策049；TEST-PLAN §6 行70）
- 注：是否严格「≥」（等于即算完成）以 feature_inventory 5.11「≥目标」为准；超额如何处理见待裁决 PD-7。

### JT-6 ★ 同一天多次打卡要累加成当日累计再比目标
同一天多次打卡的数量要累加成当日累计，再与当日目标比较是否完成——不是取单次最大值、也不是每次单独判定。
（出处：prd 行574 S10；feature_inventory_v2 5.11 行146；schema §10.1 行979-983）
- 边界：每条打卡必须归属唯一一条净土念佛愿，不允许多归属（schema 行981-983）。

### JT-7 ★ 「当日」按用户手机本地时区切分，禁用数据库 CURRENT_DATE
判断某声念佛计入哪一天，按个人打卡口径 = 用户手机本地时区，严禁用数据库 CURRENT_DATE 当「今天」。
（出处：CLAUDE.md §1 行17 时区四层）
- 边界：净土念佛属个人修持打卡，跟手机本地时区，不用班级时区。
- 边界：补录时按填写的真实日期归日，仍以个人本地日为单位。

### JT-8 打卡填真实数量，可补录过去、禁未来，无记录默认 0
打卡填的是实际念佛数量（真实数），系统不臆造；可补录任意过去日期（含今天，禁未来），补录即时生效，没有记录的日子默认为 0。
（出处：feature_inventory_v2 5.11 行146、5.8 行143，决策093；prd 行115）
- 边界：净土无内加行式限时锁定，补录不受「过期锁定」例外约束（该例外仅限内加行）。

### JT-9 师兄可自调节奏，但号别本身锁定不可换
师兄可自主调整节奏（改每日目标 / 起始日）无需审批并留痕；但三选一的号别（5000/7500/900 对应哪种念诵）本身锁定不可换。
（出处：prd 行463+857；feature_inventory_v2 5.4 行139，决策085；号别锁定见 requirements_master §8 行128）
- 注：「改每日目标」与「三选一锁定」如何共存（改目标是否等于变相换号）见待裁决 PD-9。

### JT-10 师兄端只显示当日 ✅/⬜，隐藏总累计目标
净土念佛为每日型，师兄端显示当日完成 / 未完成（✅/⬜），并隐藏历史总累计目标，不给累计压力。
（出处：prd 决定20 行2767、决定21 行2768、行574 S10）
- 边界：净土无周目标，不走 X/Y 分数显示，只出 ✅/⬜。

### JT-11 净土念佛为终生功课，毕业后仍可继续
净土念佛作为终生功课，毕业后仍可继续；这属于愿的生命周期，不改变每日完成制的当日达标口径。
（出处：feature_inventory_v2 行46，决策098）
- 注：这里被举例为「终生愿」，而建模板用的是「每日型」，两者定性有张力，见待裁决 PD-10。

## 三、入行 · 计数判例

> ⚠️ **重要差异**：入行的「座」与加行的「座」定义**完全不同**——加行净观修需 ≥30 分钟才 1 座（JX-1），入行观修**打卡 1 次就 1 座、时长不限**（RX-1）。规格明确警告两者勿混用（design_v2_decisions 行3246/3269）。这是本模块最易被误实现的点。

### RX-1 ★ 观修 1 次打卡 = 1 座，与时长无关
入行观修每打卡 1 次就记 1 座，与本次时长无关；时长选填、仅留档，不参与座次计算。
（出处：**大纲行377-379「入行论观修…每周观修 3 座以上，每座时间不限」**（最高依据·直接支持，加行/入行座定义差异的根源）；design_v2_decisions 决策050 行5134+5136、行3250；requirements_master §9 行132）
- 边界：同一天打卡 2 次 = 2 座；一天内多座全计入本周，观修无每日封顶。
- 边界：填时长 1 分钟也算 1 座，App 不做最低时长门槛校验。
- 边界：与加行明确不同——加行需 ≥30 分才 1 座、且有碎片说法；入行无时长门槛、无碎片池，勿混用（决策050 行3246/3269/5144）。

### RX-2 观修每周目标为「≥3 座 / 自然周」，自然周 = 周一至周日
入行观修每周目标为 ≥3 座 / 自然周，自然周定义为周一至周日。
（出处：requirements_master §9 行132；决策050 行3250、行5135；feature_inventory_v2 §5.12 行147）
- 边界：恰好 3 座 = 达标；2 座 = 未达标。
- 边界：进度展示为「本周已完成 X / 3 座」，基于本周计数而非总累计。

### RX-3 ★ 按周独立计数，周一清零、从 0 重新计
入行观修按周独立计数、不跨周累计；每周座次在周一清零、从 0 重新计。
（出处：决策050 行5138、行3250；design_v2_summary 行203；feature_inventory_v2 §5.12 行147；6630 变更日志）
- 边界：清零指「用于判定本周是否达标的座次计数归零」，打卡历史记录本身不删、仍留档。
- 边界：无碎片池、无余额结转的载体（决策050）。

### RX-4 ★ 本周超额的座次不结转下周
入行观修本周超过 3 座的部分不结转到下一周，下周仍需重新累计 ≥3 座。
（出处：决策050 行5138；design_v2_summary 行203-204）
- 边界：例：本周打卡 5 座，下周从 0 起，多出的 2 座不带入下周。
- 边界：超额座次仍如实记入个人总累计 / 功德回向，只是不用于满足下周达标。

### RX-5 ★ 「本周」边界按班级时区（cohort.timezone）的自然周算，禁用 CURRENT_DATE
入行观修每周清零 / 重置的时间锚点，按班级时区的自然周计算，不得用数据库 CURRENT_DATE。
（出处：决策050 行3250「按 cohort 时区自然周」；CLAUDE.md §1 行17；requirements_master §0 行54）
- 边界：跨时区师兄（如手机本地 = 纽约、班级时区 = 北京）周日深夜打卡，按班级时区可能已算下周，需按班级时区判归属周。
- 注：这与「个人打卡跟手机本地时区」存在张力（打卡当日口径 vs 每周窗口口径可能用不同时区），见待裁决 PD-13。

### RX-6 观修与观音心咒是两条独立修持项，座次只统计观修
入行观修与观音心咒是两条独立修持项，座次计数只统计观修那一条愿，不与心咒遍数混算。
（出处：requirements_master §9 行132；prd §4 行430；design_v2_summary 行223-224）
- 边界：观音心咒是「每日制」（每天 ≥1000 遍），清零 / 达标口径与观修「每周制」不同，不适用周一清零。
- 边界：师兄可只做其一（另一条置暂停，至少留一条在修）；被暂停的观修愿不再参与本周座次判定（prd 行431；D-T1-2 行401）。

## 四、学经 · 计数判例

### XJ-1 ★ 心经是每日型 auto 愿，每天读诵，目标 1-9 遍
学经固定功课「心经」是一条系统自动建的每日型愿，师兄每天需读诵，目标遍数落在 1-9 遍范围内。
（出处：requirements_master §10 行136；schema §13 行2587；design_v2_decisions 决策051 行5097-5109）
- 边界：每日型愿逐日独立判定、不跨日累计（同净土每日完成制精神）。

### XJ-2 ★ 心经每日目标由后台模板设定，cohort 可覆盖，师兄按模板建愿
心经每日目标遍数（1-9）由 program 级模板在后台设定，班级可覆盖，师兄入班按模板建愿时目标取模板设定值。
（出处：决策051 行5102-5107；feature_inventory_v2 §5.13 行148；design_v2_summary §6.5 行206-208）
- 边界：取值优先级为「program 模板默认 → cohort 覆盖 → 师兄个人节奏调整」。
- 注：1-9 是否在配置端做硬校验、师兄能否自调到范围外，规格未明说，见待裁决 PD-19。

### XJ-3 师兄可自调心经节奏并留痕，无需审批
师兄可自行调整心经愿的个人节奏（改每日目标），改动留痕、无需审批。
（出处：决策051 行5108 + 检查051 行5120；prd 行463/857）
- 边界：auto 愿只锁项目 / 总数 / 周期，节奏可调（prd 行443）。
- 边界：auto 愿师兄不可自助改状态，只能改节奏，否则架空关怀（prd 行1096）。

### XJ-4 ★ 普贤行愿品是每日型 auto 愿，固定 1 遍/天，师兄不需调整
学经固定功课「普贤行愿品」是一条每日型 auto 愿，固定目标 1 遍/天，模板写死，师兄不需也不用调整目标遍数。
（出处：requirements_master §10 行136；schema §13 行2587；决策051 检查051 行5121；prd 行424/432）
- 边界：普贤行愿品同挂净土 + 学经两专业，但学经的每日 1 遍是独立 auto 愿 / 独立种子（schema 行2375/2411/2643）。

### XJ-5 心经与普贤行愿品均按遍数计
心经与普贤行愿品两条 auto 愿的计量方式均为遍数计（单位「遍」）。
（出处：schema §13.5 行2561-2562、行2419）
- 边界：学经全部按遍数计，无座次逻辑（schema 行1285-1286）。

### XJ-6 学经固定功课两条 auto 愿为终生型，毕业后继续
学经固定功课两条 auto 愿为终生型，师兄毕业后仍继续，不因毕业结愿。
（出处：design_v2_decisions 行3475，决策051）
- 边界：与净土念佛号精神一致，毕业不清零累计。

### XJ-7 ★ 自选经是师兄自建 custom 愿，每部一条、自定节奏 + 期限
自选经是师兄发起的 custom 愿，七部经中选一或多部，每部经建一条独立 custom 愿，师兄自定节奏（每天 N 遍或每周 N 遍）+ 期限（学期末 / 自定天数）。
（出处：requirements_master §10 行137；prd 行432；schema §13 行2588）
- 边界：custom 愿必填截止日或选终生；每日型必填每日目标、每周型必填每周目标（schema 行1463-1464/1788-1792；prd 行448）。
- 边界：custom 愿对辅导员私密、可随时删除（prd 行449/884/972）。

### XJ-8 自选经从后台配置列表里选，不能自由输入
自选经的可选经典由 admin 在后台配置，师兄新建时只能从列表选，不能自由输入；列表以大纲七经为基础、admin 可增减。
（出处：决策052 行5070-5081 + 决策130；feature_inventory_v2 §5.13 行148 / §11.15 行224；prd 行141）
- 边界：自选经走 custom 愿而非课程（schema 行2418）。

### XJ-9 ★ 抄经、拜经以遍数计（整本 = 1 遍），走 custom 愿、属自愿
抄经和拜经均以遍数为单位：抄完整本 = 1 遍、礼拜完整本 = 1 遍，走与自选经相同的 custom 愿打卡机制，目标频率师兄自定，属自愿。
（出处：决策053 行5056-5066；requirements_master §10 行137；prd 行432；design_v2_decisions 行3251）
- 边界：抄经 / 拜经的经典范围与自选经共用同一 admin 配置列表（决策052 行5081）。

### XJ-10 ★ 自选功课无硬要求：只记录、不判圆满、不影响升学
学经「自选功课」（自选经 / 抄经 / 拜经）无硬要求，只记录、不判圆满、不影响升学；固定功课才是必修判定项。
（出处：06-business-capabilities-WIP.md 行326；大纲原文 行500-501；验收报告03 行47 C5）
- 边界：custom 自发愿荒废视为自愿项、非掉队，不计入班级关怀名单（prd 行972）。
- 边界：自选经只做累计展示，不设达标门槛（数量不限）。

### XJ-11 打卡按频率展示：每日型显示今日 ✅/⬜，每周型显示 X/Y
打卡按频率展示：每日型愿显示今日 ✅/⬜（今日已打 X / 目标 Y 遍），每周型愿显示 X/Y；师兄端隐藏总累计目标。
（出处：prd §S10 行574 / 场景2 行216；决策051 行5109）
- 边界：同日多次打卡累加（prd 行574；对齐 5.7 行152）。

### XJ-12 ★ 学经留级次数上限 ≤2 次，与加行同
学经专业留级次数上限为 ≤2 次，与加行相同。
（出处：requirements_master §16 行186；schema 行482-484；feature_inventory_v2 §2.10 行97 + §5 行72；prd 行2345）
- 边界：各专业上限：加行 ≤2 / 学经 ≤2 / 净土 ≤1 / 入行 ≤1（2026-05-28 教务确认补齐学经）。
- 注：v1.0 到底是「admin 人工掌握」还是「系统硬校验」，两处出处口径不一致，见待裁决 PD-18。

### XJ-13 兼修师兄两班留级完全独立，各自毕业
兼修师兄的留级两班完全独立：学经班留级不影响另一专业班，进度错位不特别处理，各自毕业。
（出处：requirements_master §16 行189；feature_inventory_v2 §2.6 行93）
- 边界：留级次数按班计次，与「班级独立、无依赖」原则一致。

### XJ-14 留级师兄进度走人工，不再自动回拨累计
留级师兄状态置为「留级」（非在修）后，进度函数对该班返回空、走人工，不再做留级回拨累计。
（出处：schema 行478 / §12.6.5 行2157 / 行2290；prd 行45）
- 边界：v2（2026-06-01）已删除「留级次数 × 每学期周数」的回拨逻辑。
- 边界：仅「在修」状态的愿才进入状态机计算（prd 行922）。

## 五、横切 · 计数机制判例（补录 / 时区 / 座次 / 豁免 / 回向开关）

### HQ-1 ★ 补录填真实修持日期，即时生效、不受审核期限制
师兄补录打卡，填真实修持日期（过去或今天皆可），数据落在真实那天，即时生效、不受审核期限制。
（出处：requirements_master §11 行142 + 附录D 行371-372 / 决策#190）
- 边界：跨已审半学期的旧补录直接计入，不强制重审（附录D 行372）。
- 边界：补录不联动——暂停不顺延截止日、起始日改动不联动历史（附录D 行373）。
- 边界：内加行限时愿是补录的唯一例外，过期后不可补（见 HQ-4）。

### HQ-2 补录禁未来日期，最晚不得晚于今天
打卡日期不得晚于今天（禁未来日期），数据库层有硬约束。
（出处：schema 行1582 / TEST-PLAN §1 行30 / feature_inventory_v2 §5.8 决策093）
- 边界：日期 == 今天允许（是「不晚于」，不是「早于」）。
- 边界：没有记录默认为 0，系统不臆造（requirements_master §11 行141）。
- 📌 PD-24 已裁决（2026-07-04）：「今天」按**手机本地时区**判；DB 硬闸放宽一天兜底。

### HQ-3 ★ 座次由时长自动判定（≥30 分 = 1 座 / <30 分 = 0 座，无 0.5 座）
单笔净观修 ≥30 分算 1 座、<30 分算 0 座，无 0.5 座；座次由系统按时长自动判定。
（出处：schema §12.3 行1913-1937 / requirements_master §7 行111-116 / 决策#189+048）
- 边界：超过 30 分钟仍只记 1 座、不可拆（行1913）。
- 边界：编辑打卡时，只有时长变化才重判座次（行1926-1929）。
- 边界：只填净观修时间，前后念诵不计（requirements_master §7 行117）。
> 与加行节 JX-1/JX-2 同源，此处从横切机制角度复述。**注意：仅加行适用，入行座次不看时长（见 RX-1）。**

### HQ-4 ★ 内加行为限时愿，过截止期后不可再补录
内加行（6×10 万）为限时愿，截止期 = 该班起始日 + 年限（默认 4 年，按建班配置、非硬编码）；过截止期（含 admin 已延长期）后不可再补录该修法。
（出处：requirements_master §7 行119 + CLAUDE.md §4 行41 / 决策073 + 决策122 / feature_inventory_v2 §5.10 行145+155、行72）
**✅ 已施工（2026-07-08·R2）**：迁移 `20260708000400_neijiaxing_expiry_lock.sql`——限时愿（template.is_time_limited）过 current_end_date（含 admin 延长）后触发器拒新打卡/补录，今天按班级时区。07 断言 HQ-4a/b/c：过期拒 / 窗口内过 / 非限时愿不受锁。91 老学员植入前置已就位。
- 边界：年限可 admin 延期兜底（延期仅 admin 有权，师兄只调窗口内节奏，决策073/086）。
- 边界：留原班重修按原班起始日起算、不重置，admin 可延期兜底（决策099/问题020）。
- 边界：转下一届重修则 4 年从新班起算、旧作废（决策099/原D11）。
- 边界：中途入班者内加行起修 / 截止日按决策073梯次，非入班当天（决策097/问题089）。
- 注：延期上限（仅 1 次 / 可多次 / 上限多少）与老学员历史数据如何生效，规格未穷尽，见待裁决 PD-26/PD-27。

### HQ-5 ★ 时区四层：个人打卡跟手机本地、班级活动按班级时区、存储 UTC、藏历 UTC+8
个人打卡的「今天」跟随师兄手机本地时区；班级集体活动（共修 / 讲考 / 考试 / 算周）的「今天」按班级时区；存储一律 UTC；藏历 / 殊胜日按 UTC+8 固定。
（出处：CLAUDE.md §1 行17 + requirements_master §2 行54 / schema 行581-583 + §16.1b 行2744-2758 / 决策075）
- 边界：禁用数据库 CURRENT_DATE 当「今天」，按对应时区取（CLAUDE.md §1 行17；schema 行2755）。
- 边界：当日在修人数聚合按班级时区取当天（schema 行1590）。
- 注：殊胜日 banner「手机本地」与藏历换算「UTC+8」两处表述需分清「用哪天查表」与「换算基准」，见待裁决 PD-28。

### HQ-6 「当日在修人数」按打卡归属算，非成员身份
当日「在修人数」按当天有没有在该班打卡来算（非按成员身份），去重统计人数，含全部确认态、不等审核。
（出处：schema 行1586-1596，2026-05-28 修正 T8 / 决策#203 + 决策102/084）
- 边界：匿名人数轴，不具名、不排名，本班范围。
- 边界：v1.0 只做当日；本周人数留 v1.5+。

### HQ-7 集体回向 / 报数聚合恒统计 share_to_collective=true 的愿
share_to_collective 恒为 true 且师兄端不可自设；集体回向 / 每周回向 / 报数聚合仅统计该开关为 true 的愿。
（出处：feature_inventory_v2 §5.19 行154，决策077 / schema 行1453-1455 + 行1645）
- 边界：简单自建 custom 愿无功课关联，自然不进聚合（决策095）。

### HQ-8 ★ 盲/聋豁免只作用于「闻思圆满」，不改任何实修计数
盲 / 聋豁免只作用于「闻思圆满」判定（盲 = 听 2 遍免看免答 = 圆满，聋 = 看 2 遍免听免答 = 圆满），不改变任何实修打卡的计数口径（座次 / 遍数 / 时长 / 达标照常）。
（出处：requirements_master §6 行102 / prd §5.10.6 行1049-1053 / feature_inventory_v2 §3.4 行109 决策080、§3.2 行107 决策091 / 决策155）
- 边界：v1.0 人工判定豁免，自动判豁免推 v1.5+（requirements_master §6 行102）。
- 边界：规格未出现任何「盲聋对座次 / 念诵遍数减免」条款——豁免仅限闻思；若 PM 欲扩到实修需另裁（见待裁决 PD-25）。
- 落地：`>=2` 这个数字同时写在 DB 视图 `v_lesson_completion`(supabase/migrations/20260712000200_completion_views.sql，62-63行)和客户端 `app/lesson/[id].tsx`(141-142行 listenTarget/readTarget)——两处互相不知情的独立硬编码，2026-07-16 三易审计已给两处加了互相指向+指回本判例的交叉引用注释，改数字时三处（含本判例）要一起改。

### HQ-9 未确认打卡师兄可改/删，审核态已降为可选核对工具
只有「未确认」的打卡记录师兄本人可改 / 删，审核确认后师兄不可改（须找辅导员 / admin）；但审核态已从「数据生效关卡」降为可选核对工具，补录即生效、聚合默认用全部数据、不分确认态。
（出处：schema §0.0.x v3.9 行267-278 / requirements_master §11 行146 + §15 行174 / 决策#191）
- 边界：确认后辅导员 / admin 可取消确认恢复未确认并留审计（schema 行270）。
- 边界：确认与否不影响计数生效，仅是核对工具（决策191）。
